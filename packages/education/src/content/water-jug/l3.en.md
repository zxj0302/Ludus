## 1. Play

You have N jugs with capacities c₁, c₂, ..., cₙ (positive integers) and an unlimited water source. Each step you may:

- **Fill(i)**: fill jug i to its capacity
- **Empty(i)**: empty jug i completely
- **Pour(i, j)**: pour from jug i to jug j until i is empty or j is full

Goal: make **some jug** contain exactly T liters.

> Classic: In "Die Hard 3", Bruce Willis must measure exactly 4 gallons using 3-gallon and 5-gallon jugs to defuse a bomb.

Try it: 3L + 5L → 4L. Can you find the shortest sequence?

## 3. Reveal

### §3.1 Formal Definition

**Water Jug Problem**:

- **Input**: N positive integers c₁, ..., cₙ (capacities), target T, with T ≤ max(c₁, ..., cₙ)
- **State**: (w₁, ..., wₙ), 0 ≤ wᵢ ≤ cᵢ
- **Initial state**: (0, 0, ..., 0) — all jugs empty
- **Operations**:
  - Fill(i): wᵢ ← cᵢ, precondition wᵢ < cᵢ
  - Empty(i): wᵢ ← 0, precondition wᵢ > 0
  - Pour(i, j): amount = min(wᵢ, cⱼ − wⱼ); wᵢ ← wᵢ − amount; wⱼ ← wⱼ + amount, precondition amount > 0
- **Goal**: ∃i such that wᵢ = T
- **Optimization objective**: minimum number of operations

### §3.2 Complexity

| Variant | Class | Notes |
|---------|-------|-------|
| Reachability decision | **P** | Bézout: T % gcd(c₁, ..., cₙ) == 0. O(N log max(c)) |
| Shortest path (fixed N) | **P** | BFS, state space = Π(cᵢ+1), O(V+E) |
| Shortest path (N variable) | **P** | Still polynomial — state space is independent of N, depends on capacities |
| Min operations (general graph BFS) | **P** | Standard unweighted graph shortest path |

**Why P, not NP?** State space size = Π(cᵢ+1), where cᵢ is counted by value (not bit-length). For 2-jug problems with c₁, c₂ ≤ 12: at most 169 states — BFS in milliseconds. Even the 3-jug case with max capacity 12: at most 2197 states — negligible. This is a classic polynomial-time solvable problem.

### §3.3 The Math: Bézout's Identity and GCD

#### Theorem (Bézout's Identity)

> For any non-zero integers a, b, there exist integers x, y such that **ax + by = gcd(a, b)**. Moreover, gcd(a, b) is the smallest positive integer expressible as an integer linear combination of a and b.

**Necessity proof sketch**: Every operation (fill, empty, pour) changes water amounts by integer linear combinations of capacities. Therefore, in any reachable state, each wᵢ can be expressed as Σ kⱼ·cⱼ (kⱼ integers), hence is a multiple of gcd(c₁, ..., cₙ). If T is not divisible by GCD, it is forever unreachable.

**Sufficiency proof sketch**: By the extended Euclidean algorithm, integers x, y exist with ax + by = g = gcd(a, b). Through appropriate fill/empty operation sequences, we can realize any multiple of g, thus any g-multiple is reachable.

#### Examples

| Capacities (a, b) | GCD | Achievable Targets |
|-------------------|-----|-------------------|
| (3, 5) | 1 | `{1, 2, 3, 4, 5}` — all |
| (4, 6) | 2 | `{2, 4, 6}` — evens only |
| (6, 10) | 2 | `{2, 4, 6, 8, 10}` — evens only |
| (5, 7) | 1 | `{1, 2, 3, 4, 5, 6, 7}` — all |
| (8, 12) | 4 | `{4, 8, 12}` — multiples of 4 only |
| (8, 12, 20) | 4 | `{4, 8, 12, 16, 20}` — 3-jug case |

#### Corollary: Sufficient Condition for Generating Puzzles

Pick any two coprime capacities (a, b) where gcd(a, b) = 1. Then for all T ≤ max(a, b), the puzzle (a, b, T) is solvable. This is the most common pattern used by the generator.

### §3.4 State Space Analysis

2-jug problem: state space = (c₁+1)(c₂+1). Each state has at most 2 fills + 2 empties + 2 pours = 6 outgoing edges.

| Max Capacity | 2-Jug State Space | 3-Jug State Space |
|-------------|------------------|------------------|
| 5 | 36 | 216 |
| 8 | 81 | 729 |
| 12 | 169 | 2197 |

### §3.5 Step Upper Bound Analysis

BFS expands layer by layer, guaranteeing the shortest path. But what is the **maximum** possible shortest path length? Knowing this bound is important for two reasons: (1) it tells us how deep BFS must search in the worst case, and (2) it provides the denominator in the difficulty formula (§5.4).

#### The Trivial Graph Bound

Since BFS visits each state at most once, the shortest path length cannot exceed the state space minus one:

```
maxDepth ≤ stateSpace − 1
```

For (3,5): stateSpace=36, so maxDepth ≤ 35. For (11,12): stateSpace=156, so maxDepth ≤ 155. But this bound is **far from tight** — actual optimal depths are much smaller.

#### The sum(capacities) Bound for 2-Jug Problems

For two jugs, a much tighter bound exists:

> **Theorem**: For capacities a and b, the BFS shortest path length ≤ a + b − gcd(a, b).

**Intuition**: Each Fill adds exactly one jug's capacity to the total water; each Empty removes exactly one jug's capacity. Total water is always between 0 and a + b. The Extended Euclidean Algorithm constructs a solution path: by alternately filling one jug and pouring to the other, any achievable target can be reached. This construction takes at most a + b − gcd(a, b) steps, and BFS will not return a longer path.

**Formal argument** (gcd = 1 case): By Bézout's Identity, there exist integers x, y such that ax + by = 1. If x > 0, repeatedly fill jug a and pour into jug b (emptying b when full); if y > 0, do the symmetric operation. Each "fill then pour" cycle costs at most 2 operations, and the total number of operations ≤ |x| + |y| ≤ a + b − 1 (a known property of the minimal coefficient pair from the Extended Euclidean Algorithm).

**gcd > 1 case**: Scale down by g: we are effectively solving for capacities a/g and b/g with target T/g. The bound becomes (a + b) / g − 1.

#### Tightness Examples

The bound is tightest when capacities are consecutive integers (which are always coprime) and the target is 1:

| Capacities (a, b) | gcd | Target | sum(caps) Bound | Actual BFS Depth | Ratio |
|-------------------|-----|--------|-----------------|------------------|-------|
| (3, 5)            | 1   | 1      | 8               | 6                | 75%   |
| (5, 7)            | 1   | 1      | 12              | 8                | 67%   |
| (7, 11)           | 1   | 1      | 18              | ≈16              | ≈89%   |
| (11, 12)          | 1   | 1      | 23              | ≈21              | ≈91%   |
| (4, 6)            | 2   | 2      | 4               | 3                | 75%   |
| (8, 12)           | 4   | 4      | 4               | 4                | 100%  |

Consecutive capacities (like 11 and 12) are always coprime, and the Extended Euclidean Algorithm needs the most steps to reach coefficient 1, so the actual depth is closest to the theoretical bound. By contrast, (3,5)→1's actual depth of 6 is well below the bound of 8 — for small capacities the bound is still conservative but far tighter than the state-space bound of 35.

#### The Bound in Code

The current difficulty system uses:

```
maxDepth = max(sum(capacities), 6)
```

The `max(..., 6)` floor ensures that tiny puzzles like (2,3)→1 still get meaningful difficulty scores. This formula is both mathematically principled and empirically adequate, covering all practically occurring BFS depths.

#### N-Jug Generalization

For N jugs, a conservative upper bound is:

```
maxDepth ≤ sum(capacities) / minGCD
```

where `minGCD = gcd(c₁, ..., cₙ)`. Total water changes by at most one capacity per operation, and the granularity of achievable states is minGCD. For 3-jug problems with capacities ≤ 12: sum ≤ 36, worst-case bound 36. In practice, optimal depths rarely exceed 25 even for 3-jug puzzles — which is why the old code used 25 as an empirical constant. The current formula `max(sum(capacities), 6)` is both rigorous and empirically sufficient.

## 4. Solve

### §4.1 BFS Algorithm Pseudocode

```
Algorithm BFS-WaterJug(capacities c[1..n], target T):
  Input:  capacities array, target amount
  Output: shortest operation sequence (or "unsolvable")

  root ← (0, 0, ..., 0)
  visited ← {root}
  queue ← [root]
  parent[root] ← null

  while queue is not empty:
    state ← queue.dequeue()
    if ∃ i such that state.jugs[i] == T:
      return reconstructPath(state, parent)

    OPS ← legalOperations(state)
    for each op in OPS:
      next ← applyOp(state, op)
      if next not in visited:
        visited.add(next)
        parent[next] ← (state, op)
        queue.enqueue(next)

  return "unsolvable"
```

### §4.2 Correctness

- **Completeness**: BFS systematically explores all reachable states. Since state space is bounded (≤ Π(cᵢ+1)), BFS will find a solution in finite steps if one exists.
- **Optimality**: BFS expands by depth layers. All depth-d states are explored before depth d+1, so the first solution found is the shortest path. This is a core property of unweighted-graph BFS — every edge costs the same (1 step).
- **Complexity**: time O(V + E), space O(V), where V = reachable states, E = total outgoing edges. For 2-jug c₁, c₂ ≤ 12: V ≤ 169, E ≤ 169 × 6 ≈ 1014, milliseconds.

### §4.3 Solver Method Comparison

| Method | Time | Space | Optimal | Completeness | Use Case |
|--------|------|-------|---------|-------------|----------|
| **BFS** | O(Π(cᵢ+1)) | O(Π(cᵢ+1)) | ✅ guaranteed | ✅ complete | Small capacities (cᵢ ≤ 12) — this implementation |
| DFS | O(Π(cᵢ+1)) | O(max depth) | ❌ not guaranteed | ✅ complete | Reachability only |
| Bézout Theorem | O(N log max(c)) | O(1) | ❌ N/A | ✅ decision only | Fast solvability check |
| Extended Euclidean | O(log min(a,b)) | O(1) | ❌ N/A | ✅ decision + coefficients | 2-jug GCD=1 direct construction |
| A* | O(V log V) | O(V) | ✅ guaranteed | ✅ complete | Large state spaces needing heuristic guidance |
| IDA* | O(bᵈᵉᵖᵗʰ) | O(d) | ✅ guaranteed | ✅ complete | Memory-constrained deep search |

For this game (cᵢ ≤ 12), BFS is the optimal choice: simple implementation, optimality guarantee, sufficient speed.

## 5. Create

### §5.1 Solvability Guarantee (Necessity & Sufficiency)

**Necessity**: Bézout's Identity gives a necessary condition — T must be a multiple of gcd(c₁, ..., cₙ). After randomly selecting capacities, the generator computes the GCD, then randomly picks T from the set of achievable targets.

**Sufficiency**: If T % gcd == 0, a sequence of operations **always exists**. This is jointly guaranteed by Bézout's Identity and BFS completeness.

```typescript
function pickTarget(capacities: number[]): number {
  let g = capacities[0];
  for (let i = 1; i < capacities.length; i++)
    g = gcd(g, capacities[i]);
  const maxCap = Math.max(...capacities);
  const achievable: number[] = [];
  for (let t = g; t <= maxCap; t += g)
    achievable.push(t);
  return achievable[randomIndex(achievable.length)];
}
```

### §5.2 Uniqueness Discussion

BFS always returns **some** shortest path, but does not guarantee **uniqueness**. Multiple equally optimal paths may exist. For example:

- 3L+5L→4L: shortest = 6 steps. Multiple different 6-step paths exist (e.g., fill 3L first vs. fill 5L first).
- When gcd(a,b) = 1 and capacities are small, there are typically multiple symmetric optimal solutions.

The generator records the shortest path length from BFS for difficulty scoring, but does not claim the path is unique.

### §5.3 Known Optimal Solution

BFS's layer-by-layer expansion mathematically guarantees optimality — the first solution found is the shortest path. No additional verification is needed.

The generator after puzzle creation:
1. Calls `solveWaterJug(state)` running BFS
2. If `solvable = true`, records `solutionLength` (shortest step count)
3. Stores `solutionLength` in `level.optimalSteps`
4. Passes it to `computeWaterJugDifficulty()` for difficulty scoring

### §5.4 Difficulty Factors & Formula

#### Difficulty Score Formula

```
depthScore   = round((min(optimalDepth, maxDepth) / maxDepth) × 80)
spaceBonus   = round(min(stateSpace / 2197, 1) × 20)
score        = min(depthScore + spaceBonus, 100)
```

Where:
- `optimalDepth` is the BFS-found shortest path length
- `maxDepth = max(sum(capacities), 6)` — the mathematical upper bound derived in §3.5
- `stateSpace = Π(cᵢ+1)` — total number of reachable states
- `2197 = 13³` — maximum state space for 3 jugs × capacity 12

The formula has two components:
1. **Depth score (0–80)**: optimal steps as a fraction of the theoretical maximum — the dominant factor
2. **State-space bonus (0–20)**: larger state spaces impose higher cognitive burden even at the same depth

The `max(..., 6)` floor ensures tiny puzzles like (2,3)→1 still get meaningful difficulty scores.

#### Difficulty Factor Contribution Table

| Factor | Weight | Description |
|--------|--------|-------------|
| Optimal path depth | ★★★★★ | Most direct factor: deeper → more steps → harder |
| Capacity magnitude | ★★★★ | Larger capacities → larger state space → more search |
| Jug count | ★★★ | 3 jugs ≈ capacity cubed in state space, significantly increases complexity |
| GCD relationship | ★★ | GCD = 1 enables more constructive solutions (more paths); GCD > 1 tighter constraints |
| Target magnitude | ★ | Target near max capacity typically requires more steps |
| State space size | ★ | Direct 0–20 bonus contribution, highly correlated with capacity and jug count |

### §5.5 Level Generator Pseudocode

```
Algorithm GenerateWaterJugLevel(difficultyRange):
  Input:  [scoreMin, scoreMax]
  Output: Level { initialState, difficulty, optimalSteps, ... }

  // 1. Determine capacity ranges from difficulty tier
  if scoreMax ≤ 33:
    capMin, capMax ← 2, 5;  numJugs ← 2
  else if scoreMax ≤ 66:
    capMin, capMax ← 5, 8;  numJugs ← random(2, 3)
  else:
    capMin, capMax ← 8, 12; numJugs ← random(2, 3)

  bestResult ← null; bestDistance ← ∞

  // 2. Rejection sampling: up to 100 attempts
  for attempt in 1..100:
    capacities ← [random(capMin, capMax) for _ in 1..numJugs]
    // Ensure not all jugs have the same capacity
    if numJugs ≥ 2 and capacities[0] == capacities[1]:
      capacities[1] ← random(capMin, capMax)

    // 3. Pick target from non-trivial candidates (prefer harder half)
    candidates ← pickTargetsByDifficulty(capacities)
    target ← candidates[random(0, ceil(|candidates|/2) - 1)]  // first half only

    if not isSolvable(capacities, target): continue

    // 4. BFS solve
    state ← createInitialState(capacities, target)
    solution ← solveWaterJug(state)
    if not solution.solvable: continue
    optimalSteps ← solution.stats.solutionLength
    if optimalSteps < 3: continue  // Reject trivial puzzles (≤ 2 steps)

    // 5. Compute difficulty score
    difficulty ← computeWaterJugDifficulty(state, optimalSteps)
    score ← difficulty.score

    // 6. If score falls in requested range, accept immediately
    if scoreMin ≤ score ≤ scoreMax:
      return { ..., initialState: state, difficulty, optimalSteps, ... }

    // 7. Otherwise track best candidate (closest to requested range)
    distance ← score < scoreMin ? scoreMin - score : score - scoreMax
    if distance < bestDistance:
      bestDistance ← distance; bestResult ← (state, optimalSteps, difficulty)

  // 8. Fallback: return best candidate found
  if bestResult exists: return bestResult as Level

  // 9. Ultimate fallback: classic (3,5) → 4 puzzle
  return classicLevel(3, 5, 4)
```

### §5.6 Verification Checklist

Every generated level must pass the following checks before returning:

- [x] `isSolvable(capacities, target)` → true (Bézout guarantee)
- [x] `target > 0` and `target ≤ max(capacities)`
- [x] At least 2 jugs, capacities ≥ 2
- [x] BFS `solution.solvable` → true (empirical verification)
- [x] `optimalSteps > 0` — target is reachable and not the initial state
