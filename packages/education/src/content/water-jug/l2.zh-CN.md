## 1. 玩 · Play

你有几个不同容量的水壶和一个无限水源。你可以：
- **装满**一个水壶到满
- **倒空**一个水壶
- **倒水**从一个壶到另一个壶，直到源壶空了或目标壶满了

目标：让**某一个壶**中的水量恰好等于目标值。

**经典谜题**：一个 3 升壶和一个 5 升壶，如何量出正好 4 升水？

试试看！用 3L 和 5L 壶量出 4L → 用 5L 和 8L 壶量出 7L → 挑战更复杂的谜题！

> 💡 操作提示：**点击壶体**选中一个壶，再点击另一个壶完成倒水。也可以直接点「装满」「倒空」按钮，或使用键盘快捷键 `1`/`2`（选壶）、`F`（装满）、`E`（倒空）。

## 2. 思考挑战 · Think

> 给定容量分别为 a 和 b 的两个壶，哪些目标水量是可以量出来的？哪些不可能？为什么？

提示：想想这个问题和最大公约数 (GCD) 有什么关系。

- 如果两个壶容量分别是 6 和 10，能量出 3 升吗？能量出 2 升吗？
- 试几个例子：(3,5)→4 可解，但 (6,10)→3 不可解。注意到什么规律？
- 能否不用动手操作，光看数字就判断一个目标是否可达？

## 3. 揭示 · Reveal

### 问题定义

**倒水问题 (Water Jug Problem / Die Hard Puzzle)**：

> 给定 N 个水壶，容量分别为 c₁, c₂, ..., cₙ（正整数），以及目标水量 T。每一步可以选择：装满一个壶、倒空一个壶、或从一个壶倒水到另一个壶。问是否存在一系列操作使得某个壶中恰好有 T 升水。

### 复杂度归类

倒水问题的复杂度取决于如何定义输入规模：

- **判定问题**：**P** — 只需检查 T % gcd(c₁, ..., cₙ) == 0，O(N log max(c)) 时间
- **最短步数**：**P** — 状态空间 = Π(cᵢ+1)，BFS 多项式时间可解
- **N 可变的一般情形**：判定属于 P，最短路径也属于 P（状态空间仍多项式）

> 📘 属于 **§13 数论** 领域。

### 数学本质：裴蜀定理 (Bézout's Identity)

倒水问题的可解性完全由**最大公约数 (GCD)** 决定：

> 两个壶容量 a、b 的量水问题中，**恰好可以量出所有 gcd(a, b) 的倍数**（且不超过 max(a, b)）。

这就是**裴蜀定理**：存在整数 x, y 使得 ax + by = gcd(a, b)。它保证了：目标 T 可达 ⇔ T 是 gcd(a, b) 的倍数且 T ≤ max(a, b)。

扩展到 N 个壶：能量出的水量是 gcd(c₁, ..., cₙ) 的所有倍数。

**关键推论**：如果 gcd(a, b) = 1，则**任意**不超过 max(a, b) 的目标都可达！这是生成可解关卡的基石。

### 状态空间

状态 = (w₁, w₂, ..., wₙ)，其中 0 ≤ wᵢ ≤ cᵢ。状态空间大小 = ∏(cᵢ + 1)。

- 2 壶，容量 ≤ 5：最多 36 种状态
- 2 壶，容量 ≤ 12：最多 169 种状态
- 3 壶，容量 ≤ 8：最多 729 种状态

这就是为什么 BFS 可以秒解的原因——状态空间不大。有趣的是，步数也有明确上界：对 2 壶问题，最优解步数不会超过 a+b−gcd(a,b)（约等于容量之和）。所以即使最难的 (11,12)→1 也只需约 21 步，远低于状态空间大小 156。

### 难度档位

| 档位 | 分数 | 容量范围 | 壶数 | 典型最优步数 |
|------|------|---------|------|-------------|
| 简单 | 1–33 | 2–5 | 2 | ≤5 步 |
| 中等 | 34–66 | 5–8 | 2–3 | 5–10 步 |
| 困难 | 67–100 | 8–12 | 2–3 | ≥10 步 |

## 4. 求解 · Solve

求解器使用 **宽度优先搜索 (BFS)**：

```
BFS(初始全空状态):
  visited = {初始状态}
  queue = [初始状态]
  while queue 非空:
    当前 = queue.dequeue()
    if 某个壶水量 == 目标: return 路径
    for 每个合法操作(装满/倒空/倒水):
      下一状态 = apply(当前, 操作)
      if 下一状态 不在 visited:
        visited.add(下一状态)
        queue.enqueue(下一状态)
  return "无解"
```

- **状态去重**：用哈希集合记录已访问状态，避免无限循环
- **最短路径保证**：BFS 按层搜索，第一个找到的解一定是最优解
- **完备性**：如果解存在，BFS 一定会找到它（状态空间有限）
- **效率**：状态空间受容量限制，BFS 可在毫秒内完成搜索

## 5. 出题 · Create

关卡生成器提供三种保证：

- **可解性（裴蜀定理）**：目标水量必须是 GCD(capacities) 的倍数。生成器在随机选择容量和目标后，用 `isSolvable()` 验证，不可解则重试。
- **已知最优解**：生成后用 BFS 求解，记录最短路径长度。这个值同时用于计算难度分数。
- **难度可控**：通过容量范围控制（简单 2–5 / 中等 5–8 / 困难 8–12），壶数影响状态空间大小，间接控制最优深度。
