## 1. Play

You have several jugs of different capacities and an unlimited water source. You can:
- **Fill** a jug completely
- **Empty** a jug completely
- **Pour** water from one jug to another until either the source is empty or the destination is full

Goal: get **exactly** the target amount of water in any one jug.

**Classic puzzle**: With a 3L and 5L jug, how do you measure exactly 4L?

Give it a try! 3L+5L → 4L → then 5L+8L → 7L → challenge harder puzzles!

> 💡 Controls: **Click a jug** to select it, then click another to pour. Use the Fill/Empty buttons, or keyboard: `1`/`2` (select jug), `F` (fill), `E` (empty).

## 3. Reveal

### Problem Definition

**Water Jug Problem (aka Die Hard Puzzle)**:

> Given N jugs with capacities c₁, c₂, ..., cₙ (positive integers) and a target amount T, at each step you may: fill a jug, empty a jug, or pour from one jug to another. Is there a sequence of operations that puts exactly T liters in some jug?

### Complexity

The complexity depends on how input size is defined:

- **Decision**: **P** — just check T % gcd(c₁, ..., cₙ) == 0, O(N log max(c))
- **Shortest path**: **P** — state space = Π(cᵢ+1), BFS in polynomial time
- **General case (N variable)**: both decision and shortest path remain in P (state space still polynomial)

> 📘 Category: **§13 Number Theory**.

### The Math: Bézout's Identity

Solvability is entirely determined by the **greatest common divisor (GCD)**:

> With two jugs of capacities a and b, you can measure **exactly all multiples of gcd(a, b)** (up to max(a, b)).

This is **Bézout's Identity**: there exist integers x, y such that ax + by = gcd(a, b). It guarantees: target T is reachable ⇔ T is a multiple of gcd(a, b) and T ≤ max(a, b).

**Critical corollary**: If gcd(a, b) = 1, then **any** target ≤ max(a, b) is achievable. This is the foundation for generating solvable puzzles.

### State Space

State = (w₁, w₂, ..., wₙ) where 0 ≤ wᵢ ≤ cᵢ. State space size = Π(cᵢ + 1).

- 2 jugs, capacities ≤ 5: at most 36 states
- 2 jugs, capacities ≤ 12: at most 169 states
- 3 jugs, capacities ≤ 8: at most 729 states

This is why BFS solves instantly — the state space is small. Interestingly, the step count also has a clear upper bound: for 2-jug problems, the optimal solution never exceeds a+b−gcd(a,b) steps (roughly the sum of capacities). So even the hardest (11,12)→1 takes only about 21 steps — far below the state space size of 156.

## 4. Solve

The solver uses **Breadth-First Search (BFS)**:

```
BFS(all jugs empty):
  visited = {initial state}
  queue = [initial state]
  while queue not empty:
    current = queue.dequeue()
    if any jug amount == target: return path
    for each valid operation (fill/empty/pour):
      next = apply(current, operation)
      if next not in visited:
        visited.add(next)
        queue.enqueue(next)
  return "unsolvable"
```

- **State dedup**: hash-set for visited states, preventing infinite loops
- **Optimal guarantee**: BFS expands by layer; first solution found is optimal
- **Completeness**: BFS will find a solution if one exists (finite state space)
- **Efficiency**: state space bounded by capacities; BFS completes in milliseconds

## 5. Create

The level generator provides three guarantees:

- **Solvability (Bézout)**: target must be a multiple of GCD(capacities). The generator validates with `isSolvable()` after random selection; retries if unsolvable.
- **Known optimal**: BFS verifies solvability post-generation and records shortest path length. This value is also used for difficulty scoring.
- **Controllable difficulty**: controlled via capacity ranges (Easy 2–5 / Medium 5–8 / Hard 8–12); jug count affects state space size, indirectly controlling optimal depth.
