# Lights Out — Complete Mathematics & Algorithms

## 1. Play

> Tip: Tap a cell to toggle itself and its four orthogonal neighbors. Turn all lights off to win.

## 2. Think

Some starting boards have **multiple solutions** — different sequences of presses that all turn off the lights. Some are **unsolvable** — no sequence works, no matter how long you try. And some have exactly **one solution**.

How does a computer tell these cases apart? And how do we deliberately generate a puzzle with exactly one solution? The answer lies in the **null space** of a linear system over GF(2).

## 3. Reveal

### 3.1 Formal Definition

**State space**: An $n \times n$ board of lights. Each light $\in \mathbb{F}_2 = \{0, 1\}$, where 0 = OFF, 1 = ON. The state vector $\mathbf{b} \in \mathbb{F}_2^{n^2}$.

**Move**: Pressing cell $(i, j)$ corresponds to a vector $\mathbf{a}_{ij} \in \mathbb{F}_2^{n^2}$ with 1s at $(i, j)$ and its four orthogonal neighbors (if they exist), and 0 elsewhere.

**Influence matrix**:

$$A = [\mathbf{a}_{11} \mid \mathbf{a}_{12} \mid \dots \mid \mathbf{a}_{nn}]^T \in \mathbb{F}_2^{n^2 \times n^2}$$

**Core equation**:

$$A\mathbf{x} = \mathbf{b} \quad (\text{all operations over } \mathbb{F}_2)$$

where $\mathbf{x} \in \mathbb{F}_2^{n^2}$ indicates which cells to press (1 = press, 0 = don't).

### 3.2 Solution Structure

The solution space for $A\mathbf{x} = \mathbf{b}$ is:

$$\mathbf{x} = \mathbf{x}_p + \mathbf{x}_h$$

- $\mathbf{x}_p$: a **particular solution** (any feasible pressing pattern)
- $\mathbf{x}_h \in \ker(A)$: homogeneous solution, satisfying $A\mathbf{x}_h = \mathbf{0}$

Thus:
- **$\ker(A) = \{\mathbf{0}\}$** (trivial null space) → $A$ has full rank → every solvable state has a **unique solution**
- **$\ker(A) \neq \{\mathbf{0}\}$** → $A$ is rank-deficient → solvable states have $2^{\dim(\ker(A))}$ distinct solutions
- **$\mathbf{b} \notin \operatorname{col}(A)$** → system is **inconsistent** → this starting board is unsolvable

### 3.3 Complexity Classification

- **Complexity Class**: **P**
- **Justification**: Gaussian elimination over GF(2) runs in $O(m^3)$ time where $m = n^2$ is the number of rows. Since the matrix is sparse (at most 5 ones per row — center + up/down/left/right), sparse elimination reduces this to $O(m^2) = O(n^4)$. Deciding existence and uniqueness of solutions is polynomial-time.

## 4. Solve

### 4.1 Algorithm: Gaussian Elimination over GF(2)

#### Idea

Form the augmented matrix $[A \mid \mathbf{b}]$ of size $n^2 \times (n^2+1)$ and perform row operations over $\mathbb{F}_2$:
- **Row swap** (permutation)
- **Row XOR** (addition modulo 2)
- No scalar multiplication needed — the only non-zero scalar in $\mathbb{F}_2$ is 1.

#### Pseudocode

```pseudo
function GF2_Gaussian_Elimination(A, b):
    // A: n² × n² matrix over GF(2)
    // b: n² × 1 vector
    n = length(b)
    M = augment(A, b)        // n × (n+1) augmented matrix
    pivot_row = 0

    for col = 0 to n-1:
        // Find pivot
        pivot = -1
        for row = pivot_row to n-1:
            if M[row][col] == 1:
                pivot = row
                break

        if pivot == -1:
            continue          // No pivot in this column, skip

        swap(M[pivot_row], M[pivot])

        // Eliminate all other rows (full RREF, not just upper triangular)
        for row = 0 to n-1:
            if row != pivot_row and M[row][col] == 1:
                XOR_row(M[row], M[pivot_row])   // row = row ⊕ pivot_row

        pivot_row += 1

    // Check consistency & back-substitute
    x = array of size n, initialized to 0
    for row = pivot_row to n-1:
        if M[row][n] == 1:
            return "NO SOLUTION"    // Inconsistent system

    // Read solution from reduced row-echelon form
    for row = 0 to n-1:
        col = first_nonzero_column(M[row])
        if col != -1:
            x[col] = M[row][n]

    // Null space basis (for non-unique solutions)
    nullity = n - pivot_row
    if nullity > 0:
        null_basis = compute_null_space_basis(M, pivot_row)
        return (x, null_basis, nullity)

    return (x, null, 0)  // Unique solution
```

#### Complexity Analysis

- Time: $O(n^6)$ naive; $O(n^4)$ with sparse matrix optimization
- Space: $O(n^4)$ for the $n^2 \times (n^2+1)$ augmented matrix
- For the standard 5×5 = 25 lights: a 25×25 matrix, negligible computation

#### Computing the Null Space Basis

When $A$ is rank-deficient ($\operatorname{rank}(A) < n^2$), the nullity is $\dim(\ker(A)) = n^2 - \operatorname{rank}(A)$. Free variables are identified during back-substitution. A basis is obtained by setting each free variable to 1 in turn (with all others set to 0) and solving for the dependent variables.

## 5. Create

> Unlike §3's formal definition, §5 addresses the core question: **how do we guarantee that a generated puzzle is well-formed?**
> A well-formed puzzle must satisfy four dimensions of guarantee, each mathematically verifiable.

---

### 5.1 Guarantee I: Solvability (Existence of a Solution)

#### Problem

Given an initial state $\mathbf{b}$, does there exist a press vector $\mathbf{x}$ such that $A\mathbf{x} = \mathbf{b}$?

#### Criterion

$$\mathbf{b} \text{ is solvable} \iff \mathbf{b} \in \operatorname{col}(A)$$

That is, $\mathbf{b}$ lies in the column space of $A$. During Gaussian elimination on the augmented matrix $[A \mid \mathbf{b}]$, if any row reduces to "all zeros on the left, 1 on the right," the system is inconsistent and $\mathbf{b}$ is unsolvable.

#### How Generation Guarantees It

- **Constructive method (recommended)**: Don't randomly generate $\mathbf{b}$. Instead, **choose $\mathbf{x}^*$ first, then compute $\mathbf{b} = A\mathbf{x}^*$**. Since $\mathbf{b}$ is by definition a linear combination of columns of $A$, it's automatically in $\operatorname{col}(A)$ → **100% solvable**.
- **Verification method**: If $\mathbf{b}$ was generated randomly, run Gaussian elimination and check for contradictory rows. If any exist → discard and retry.

> **Conclusion**: The constructive method guarantees solvability at the source. This is the default strategy for the Lights Out generator.

---

### 5.2 Guarantee II: Unique Solution

#### Problem

Even if $\mathbf{b}$ is solvable, is the solution unique? That is, could there be **multiple different** pressing patterns that all turn off the lights?

#### Criterion

$$A\mathbf{x} = \mathbf{b} \text{ has a unique solution} \iff \ker(A) = \{\mathbf{0}\} \iff \operatorname{rank}(A) = n^2 \iff \dim(\ker(A)) = 0$$

Equivalently: after Gaussian elimination, every column has a pivot — i.e., $A$ has full rank.

If $\dim(\ker(A)) > 0$, the solution space has size $2^{\dim(\ker(A))}$ — meaning multiple distinct solutions exist.

#### When is $A$ rank-deficient?

The rank of $A$ depends on the board size $n$. Known results (Anderson & Feil, 1998):

| $n$ | $\operatorname{rank}(A)$ | $\dim(\ker(A))$ | Unique solutions? |
|-----|--------------------------|-----------------|-------------------|
| 3 | 9 | 0 | ✅ All states |
| 4 | 16 | 0 | ✅ All states |
| 5 | 23 | 2 | ❌ Solvable states have $2^2 = 4$ solutions each |
| 6 | 36 | 0 | ✅ All states |

> The classic 5×5 Lights Out has a null space of dimension 2, meaning every solvable state admits 4 distinct solutions.

#### How Generation Guarantees It

- **Choose a full-rank board size** (e.g., $n = 3, 4, 6$) → unique solutions naturally. This is the strongest guarantee.
- **Or**: on rank-deficient sizes, generate $\mathbf{b}$ constructively, then enumerate all solutions (general solution = particular + null space basis combinations). Choose the one with **all-zero null space coefficients** as the canonical answer, and instruct the player to "find the solution with fewest presses" — then the optimal solution is unique.
- **Or**: among all solutions, pick the one minimizing $\|\mathbf{x}\|_0$ (fewest 1s) as the canonical optimal.

---

### 5.3 Guarantee III: Known Optimal Solution

#### Problem

Even if the solution is unique, how do we know it uses the **minimum number of presses**? For rank-deficient cases (e.g., 5×5), how do we find the optimal among multiple solutions?

#### Criterion

- If $\ker(A) = \{\mathbf{0}\}$ (full rank): the unique solution $\mathbf{x}$ is **automatically optimal** — there are no alternatives.
- If $\ker(A) \neq \{\mathbf{0}\}$: the general solution is $\mathbf{x} = \mathbf{x}_p + \sum_{i=1}^d c_i \mathbf{v}_i$, where $\{\mathbf{v}_i\}$ is a basis for the null space and $c_i \in \{0, 1\}$. We must find the **minimum-weight** solution among all $2^d$ candidates:

$$\mathbf{x}_{\text{opt}} = \arg\min_{\mathbf{x} \in \mathbf{x}_p + \ker(A)} \|\mathbf{x}\|_0$$

For Lights Out, $d$ is small (for 5×5, $d=2$ yields only 4 candidates) — brute-force enumeration suffices. Larger null spaces can be reduced to the **minimum-weight solution problem** (NP-hard in general), but Lights Out instances remain enumerable.

#### How Generation Guarantees It

**Reverse construction (most reliable)**:
1. Choose a target optimal solution $\mathbf{x}^*$ manually (controlling step count → controlling difficulty).
2. Compute $\mathbf{b} = A\mathbf{x}^*$.
3. Solve $A\mathbf{x} = \mathbf{b}$ to obtain all candidate solutions, verifying $\mathbf{x}^*$ truly has minimum weight among them:
   - If $\ker(A) = \{\mathbf{0}\}$: automatically satisfied.
   - If $\ker(A) \neq \{\mathbf{0}\}$: enumerate all $2^d$ solutions, confirm $\|\mathbf{x}^*\|_0 \leq \|\mathbf{x}\|_0$ for every candidate $\mathbf{x}$.

> **Key guarantee**: the optimality of $\mathbf{x}^*$ is verified by **exhaustive enumeration over the null space**, not by heuristic guesswork. For Lights Out's small boards, this is always feasible in polynomial time.

---

### 5.4 Guarantee IV: Difficulty Control

#### Problem

How do we quantify a Lights Out puzzle's difficulty and precisely control it during generation?

#### Difficulty Factor Framework

| Factor | Symbol | Quantification | Effect on Difficulty | Controllability |
|--------|--------|---------------|---------------------|-----------------|
| Board size | $n$ | $n \in \{3, 4, 5, 6\}$ | Larger $n$ → state space grows as $2^{n^2}$, but solving complexity grows only polynomially | **Discrete tiers** |
| Optimal step count | $\|\mathbf{x}^*\|_0$ | Number of 1s in $\mathbf{x}^*$ | More presses → more human operations needed → harder. On a 5×5 board, 5 steps vs. 12 steps is a tangible difference | **Continuously tunable** (control when choosing $\mathbf{x}^*$) |
| Null space dimension | $\dim(\ker(A))$ | $n^2 - \operatorname{rank}(A)$ | $=0$: unique answer, no fallback, purest challenge; $>0$: multiple solutions, higher tolerance, easier | **Determined by $n$** (not tunable) |
| Solution sparsity | $\rho = \frac{\|\mathbf{x}^*\|_0}{n^2}$ | Density of 1s | $\rho < 10\%$: too sparse, easy to stumble upon; $\rho > 50\%$: press-everything ≈ reset; sweet spot $\rho \in [20\%, 40\%]$ | **Continuously tunable** |
| Visual symmetry | $S$ | Degree of rotational/mirror symmetry of initial state $\mathbf{b}$ | High symmetry → humans intuit patterns → easier; no symmetry → must reason logically | **Tunable** (add symmetry constraints when choosing $\mathbf{x}^*$) |
| Pattern conspicuousness | $P$ | Number and distribution of connected lit-cell clusters in $\mathbf{b}$ | Clustered lit cells → player thinks "solve locally" → may need distant operations → harder | **Indirectly tunable** |

#### Difficulty Score Formula

$$\text{score} = \text{clip}\left( \alpha \cdot \frac{n - 2}{4} + \beta \cdot \frac{\|\mathbf{x}^*\|_0}{n^2} + \gamma \cdot (1 - S) + \delta \cdot P_{\text{scattered}}, \ 0, \ 100 \right)$$

where $\alpha = 30,\ \beta = 50,\ \gamma = 15,\ \delta = 5$ are empirical weights (to be calibrated via human playtesting).

#### Difficulty Tier Mapping

| Tier | Score Range | $n$ | $\|\mathbf{x}^*\|_0$ Range | Typical Config |
|------|------------|-----|---------------------------|----------------|
| 🟢 Beginner | 0–20 | 3 | 1–2 | 3×3, 2 moves |
| 🟡 Easy | 20–40 | 3–4 | 2–4 | 4×4, 3 moves |
| 🟠 Medium | 40–60 | 4–5 | 4–8 | 5×5, 6 moves |
| 🔴 Hard | 60–80 | 5 | 8–12 | 5×5, 10 moves, asymmetric |
| ⚫ Expert | 80–100 | 5–6 | 12+ | 6×6, 15 moves, scattered |

#### How the Generator Implements Difficulty Control

```
function generateLevel(targetDifficulty: number): Level {
    // 1. Select n and step range based on target difficulty
    const { n, stepsRange } = selectParams(targetDifficulty);

    // 2. Generate random x*, controlling 1-count within stepsRange
    const xStar = randomVectorWithWeight(n * n, stepsRange);

    // 3. Construct b = A·x*
    const b = multiplyMod2(influenceMatrix(n), xStar);

    // 4. Verify unique solution (if required)
    const rank = gf2Rank(influenceMatrix(n));
    const uniqueSolution = (rank === n * n);

    // 5. Verify optimality of x* (exhaustive over null space)
    const allSolutions = enumerateAllSolutions(A, b);
    const isOptimal = xStar.weight <= min(allSolutions.map(s => s.weight));

    // 6. Compute difficulty score
    const score = computeDifficultyScore({ n, steps: xStar.weight, symmetry: measureSymmetry(b) });

    return { initialState: b, optimalSteps: xStar.weight, uniqueSolution, difficulty: { score }, ... };
}
```

#### Difficulty Verification Loop

Every generated puzzle must pass the following checks before publication:

1. **Solvability**: $A\mathbf{x} = \mathbf{b}$ has a solution (constructively guaranteed).
2. **Optimality**: the weight of $\mathbf{x}^*$ is minimal among all solutions (exhaustively verified).
3. **Uniqueness** (if claimed): $\dim(\ker(A)) = 0$, or multiple solutions are explicitly noted.
4. **Difficulty score matches actual step count**: $\|\mathbf{x}^*\|_0$ falls within the corresponding tier range.
5. **Human playability spot-check**: randomly sample 5% of generated puzzles for manual playtesting.

|----------|----------------------|---------------------|---------------------|-------------------|----------|
