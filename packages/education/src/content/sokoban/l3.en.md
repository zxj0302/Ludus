# Sokoban — Deep Dive

## 1. Play

Same as L2.

## 2. Think

Beyond L2 questions, consider:

- How much memory does BFS need in the worst case? For 64 bytes per state and 10 million states: **640 MB** — this is why solving even "simple" levels often times out.
- Is there a polynomial-time deterministic algorithm? No — PSPACE-completeness means no such algorithm exists (assuming P ≠ PSPACE).

## 3. Reveal

### Completeness Proof Outline

Culberson (1997) proved PSPACE-completeness by reducing **Quantified Boolean Formula (QBF)** to Sokoban. QBF is the canonical PSPACE-complete problem. The reduction encodes QBF's existential/universal quantifier alternation using Sokoban's box-and-tunnel structures.

### BFS Space Complexity

With branching factor $b$ (typically 2–4) and optimal depth $d$, BFS stores up to $O(b^d)$ states simultaneously. For medium levels ($d \approx 50$), this can reach tens of millions of states, exceeding browser memory.

Hence the need for **deadlock pruning**, **symmetry reduction**, and **reachability filtering**.

## 4. Solve

### Algorithm Progression

**Stage 1: Naive BFS**
- Time $O(b^d)$, space $O(b^d)$
- Only works for $d \leq 15$

**Stage 2: BFS + Deadlock Detection** (this implementation)
- Corner deadlock detection $O(1)$
- Edge deadlock detection $O(1)$
- Typical pruning rate 30–60%, effectively reducing branching factor

> **Implementation Limitation**: Only static corner deadlocks and simple edge deadlocks are detected. More advanced cases — freeze deadlocks (boxes blocked by other boxes), 2×2 box clusters, wall-line deadlocks — are **not implemented**; actual pruning rates fall short of the theoretical upper bound.

**Stage 3: IDA* + Heuristics**
- Heuristic $h(s)$ estimates minimum remaining moves (e.g., sum of Manhattan distances from each box to its nearest goal)
- IDA* performs DFS within each depth bound, space $O(d)$, time still $O(b^d)$ but with massive constant improvement

**Stage 4: Bidirectional BFS + Precomputation**
- Search simultaneously from initial and goal states, meeting in the middle
- Precompute solutions for classic level sets and cache them

### Deadlock Detection in Detail

**Corner deadlock**: Box at $(r, c)$ satisfies:
- Not on any goal
- $(r-1, c)$ and $(r, c-1)$ are both walls → top-left corner deadlock
- (Similar checks for other three corners)

**Edge deadlock**: Box against a wall, blocked by walls on both sides along the wall. Note: only walls are checked (boxes are movable and don't cause permanent deadlocks).

```python
def is_deadlock(state, box):
    if box on goal: return False
    # corner checks
    for (dr1, dc1), (dr2, dc2) in corner_pairs:
        if wall(box.r + dr1, box.c + dc1) and wall(box.r + dr2, box.c + dc2):
            return True
    # edge checks: box against a wall, blocked by walls on both sides
    for dr, dc in [(0,1), (0,-1), (1,0), (-1,0)]:
        if wall(box.r + dr, box.c + dc):
            blocked = True
            for mdr, mdc in [(dc, dr), (-dc, -dr)]:
                nr, nc = box.r + mdr, box.c + mdc
                if not wall(nr, nc):
                    blocked = False
                    break
            if blocked:
                return True
    return False
```

## 5. Create

### 5.1 Generation Methods

| Method | Strength | Weakness | Source |
|--------|----------|----------|--------|
| **Reverse Playing** | Always solvable | Quality varies | Rolling Stone, 2000 |
| **Template Stitching** | Structurally elegant | Template design costly | Murase et al., 2008 |
| **Genetic Algorithm** | Optimize specific metrics | Computationally expensive | Ashlock, 2010 |
| **Constraint Solving (SAT/CSP)** | Precise control over properties | Slow to solve | Prünte, 2021 |

### 5.2 Reverse Playing (Recommended First)

1. Start from goal state (all boxes on goals)
2. Player performs "pull" operations (reverse outward box pulls)
3. Perform K random steps, obtain initial state
4. Forward BFS verifies solvability + confirms optimal step count

### 5.3 Difficulty Metrics

Three core factors:
- **Box count** $k$: more boxes = harder
- **Area** $w \times h$: larger space = more branching
- **Optimal steps** $opt$: more steps = harder

Difficulty formula (current implementation based on level size and box count; future versions will incorporate optimal steps):
$$\text{score} = \text{clamp}\left(40 \cdot \frac{size-20}{80} + 60 \cdot \frac{k-1}{7},\ 0,\ 100\right)$$

### 5.4 Classic Level Sets
