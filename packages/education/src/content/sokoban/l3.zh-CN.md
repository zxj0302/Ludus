# 推箱子 Sokoban — 深入算法

## 2. 思考 · Think

除了 L2 中的问题，再思考：

- BFS 在最坏情况下需要多少内存？如果每个状态 64 字节、共 1000 万状态，需要 **640 MB**——这是为什么简单关也经常"求解中"超时的根本原因。
- 是否存在**可判定的**多项式时间求解算法？不——PSPACE-完全意味着在 P ≠ PSPACE 的假设下不存在这样的算法。

## 3. 揭示 · Reveal

### 完整性证明概要

Culberson (1997) 通过将**量化布尔公式 (QBF)** 归约到 Sokoban 证明其 PSPACE-完全性。QBF 是已知的 PSPACE-完全问题。归约的核心思想是：用 Sokoban 的箱子和隧道结构模拟 QBF 的"存在/任意"量词交替。

### BFS 空间复杂度分析

设分支因子 $b$（通常 2–4），最优解深度 $d$，则 BFS 最多同时存储 $O(b^d)$ 个状态。对于中等关卡（$d \approx 50$），状态数可达数千万，超出浏览器内存限制。

因此实践中必须在 BFS 上叠加**死锁剪枝**、**对称性约简**和**可达性筛选**。

## 4. 求解 · Solve

### 算法演进

**阶段一：朴素 BFS**
- 时间 $O(b^d)$，空间 $O(b^d)$
- 仅适用于 $d \leq 15$ 的极简关

**阶段二：BFS + 死锁检测**（本实现）
- 角死锁检测 $O(1)$
- 边死锁检测 $O(1)$
- 剪枝率通常 30–60%，大幅降低有效分支因子

> **实现限制**：当前仅检测静态角死锁与简单边死锁。更高级的 freeze deadlock（箱子被其他箱子卡住）、2×2 箱子簇死锁、沿墙线死锁等**未实现**，因此实际剪枝率低于理论上限。

**阶段三：IDA* + 启发式**
- 用启发函数 $h(s)$ 估算剩余步数下界（如"每个箱子距离最近目标点的曼哈顿距离之和"）
- IDA* 在每个深度限制内执行 DFS，空间 $O(d)$，时间仍为 $O(b^d)$ 但常数优化巨大

**阶段四：双向 BFS + 预计算**
- 从初始状态和目标状态同时搜索，中间相遇
- 预计算经典关卡集的解并缓存，跳过重复求解

### 死锁检测详解

**角死锁**：箱子坐标 $(r, c)$ 满足：
- 不在任何目标点上
- $(r-1, c)$ 和 $(r, c-1)$ 均为墙 → 左上角死锁
- （四个角的检测类似）

**边死锁**：箱子贴边，且沿边两个方向均为墙。注意：只检测墙壁阻挡（箱子可移动，不构成永久死锁）。

```python
def is_deadlock(state, box):
    if box on goal: return False
    # check 4 corners
    for (dr1, dc1), (dr2, dc2) in corner_pairs:
        if wall(box.r + dr1, box.c + dc1) and wall(box.r + dr2, box.c + dc2):
            return True
    # check 4 edges: box against a wall, blocked by walls on both sides
    for dr, dc in [(0,1), (0,-1), (1,0), (-1,0)]:
        if wall(box.r + dr, box.c + dc):
            blocked = True
            for mdr, mdc in [(dc, dr), (-dc, -dr)]:
                nr, nc = box.r + mdr, box.c + mdc
                if not wall(nr, nc):
                    blocked = False
                    break
            if blocked:
                return True
    return False
```

### 5.2 反向行走法（推荐首试）

1. 从目标状态（所有箱子在目标上）出发
2. 玩家执行"拉"操作（反向往外拉箱子）
3. 随机执行 K 步，得到初始状态
4. 正向 BFS 验证可解 + 确认最优步数

### 5.3 难度度量

三个核心因素：
- **箱子数** $k$：$k$ 越大越难
- **仓库面积** $w \times h$：空间越大分支越多
- **最优解步数** $opt$：步数越多越难

难度公式（当前实现基于关卡尺寸与箱子数，后续版本将纳入最优步数）：
$$\text{score} = \text{clamp}\left(40 \cdot \frac{size-20}{80} + 60 \cdot \frac{k-1}{7},\ 0,\ 100\right)$$
