# Thief Siege — Escape Paths and Bottlenecks on a Graph

## 1. 玩 · Play

The rules are compact: each turn you place one cop on a walkable cell, then the thief moves one step. Edge exits are the thief's target. If the thief has no route to any exit, the cops win.

v1.1 scales the board by difficulty: 11×11 for easy, 15×15 for medium, and 19×19 for hard. The play loop is still about reading routes, shrinking space, and creating a trap, but now you are blocking future escape space, not just the yellow shortest path in front of you.

## 2. 思考 · Think

A common mistake is to stare only at cells adjacent to the thief. The deeper questions are:

- Among all paths from the thief to the exit set, which one is shortest?
- Which placement lengthens that shortest path or disconnects the exits entirely?
- Why do some cells behave like bridges, changing the whole board when blocked?
- If the thief knows you will keep blocking next turn, should it preserve shortest distance, reachable exits, or future branching options?

These questions turn "surround the thief" into a graph path, cut, and alternating-game problem.

## 3. 揭示 · Reveal

### 3.1 Graph Model

Represent the board as an undirected graph $G=(V,E)$:

- $V$: every `floor` and `exit` cell
- $E$: edges between 4-neighbor walkable cells
- $s \in V$: the thief position
- $T \subseteq V$: all exit cells
- $C \subseteq V$: cells occupied by cops

The current walkable graph is $G' = G[V \setminus C]$. The thief can still escape iff there exists a path from $s$ to some $t \in T$ in $G'$.

### 3.2 BFS and the Shortest Escape Path

Because each move has equal cost, BFS expands from $s$ by distance layers. The first reached exit gives the shortest escape length:

$$d(s,T)=\min_{t\in T} d(s,t)$$

If the queue is exhausted without reaching an exit, $s$ and $T$ are disconnected, so the thief is trapped.

### 3.3 Bottleneck Intuition

Placing a cop deletes one vertex. If a cell lies on many paths from $s$ to $T$, it is a bottleneck candidate; blocking it may force long detours or disconnect every route.

v1 used an "escape BFS + path-first blocking" heuristic. v1.1 adds alternating search: cop nodes enumerate `place`, thief nodes enumerate `step`, cops choose the move that minimizes the thief's evaluation, and the thief chooses the move that maximizes it. That is the minimax intuition for a finite pursuit-evasion game.

### 3.4 Adversarial Search Contract

The full game tree grows quickly with board size, placeable cells, and turn count, so the implementation uses a tiered contract:

- **Easy 11×11**: generation runs `copHasWinningStrategy` with a generous budget and accepts only openings where the search proves a cop win.
- **Medium 15×15 / Hard 19×19**: generation prefers bottleneck or corridor-like structures, then runs shallow adversarial checks to reject obvious thief-favored openings.
- **Runtime AI**: first tries adversarial search; if time or depth runs out it reports `bounded`; if no legal adversarial move is available it falls back to greedy BFS.

So medium and hard "winnability" is an engineering guarantee, not a claim that every future branch has been mathematically proved.

## 4. 求解 · Solve

The visualization still starts with BFS because it is the clearest layer:

```text
EscapeBFS(state):
  blocked = cops
  queue = [thief]
  parent[thief] = null

  while queue not empty:
    current = dequeue(queue)
    if current is an exit:
      return reconstructPath(parent, current)

    for each 4-neighbor next:
      if next is walkable and next not blocked and next not visited:
        parent[next] = current
        enqueue(next)

  return no escape path
```

BFS costs $O(|V|+|E|)$. It tells us whether an escape path exists right now and emits the `escape-path` visualization.

The adversarial engine runs bounded alpha-beta search above that:

```text
Search(state, depth, alpha, beta):
  if thief escaped: return +10000
  if thief trapped: return -10000
  if timeout or depth == 0: return Evaluate(state)

  if thief turn:
    choose the step with maximum score
  else:
    choose the placement with minimum score
```

The evaluation combines shortest escape length, number of reachable exits, and remaining cop budget. Easier escape means a higher thief score; being cut off means a better cop position.

The visualization reads `trace.visualizationData.escapePath` and maps the reconstructed BFS path back onto board cells. Yellow cells show the current shortest escape route, while exits, cops, and the thief keep distinct markers so you can see exactly what a placement blocks.

On the web, `thief-siege` also registers an `ai-move` Worker task. Thief turns prefer the Worker path so 15×15 and 19×19 searches do not freeze the UI. If the Worker is unavailable, the code falls back through `getAIMoveAsync` and then the synchronous path. Solver stats expose the tier as `escape-adversary/perfect`, `escape-adversary/bounded`, or `escape-adversary/bfs`.

## 5. 出题 · Create

The generator uses an irregular mask:

1. Pick a size: 11, 15, or 19 depending on the difficulty tier.
2. Generate a playable region from an ellipse with light random wobble; outside cells become obstacles.
3. Mark the playable boundary as `exit`; interior cells become `floor`.
4. Add a few interior obstacles according to difficulty while keeping the center area safe.
5. Place the thief near the center.
6. Run BFS to verify that the initial state has at least one escape path.
7. Run the hybrid win gate:
   - Easy: `copHasWinningStrategy(state, { maxDepth: Infinity })` must be true.
   - Medium/hard: the shortest path must expose enough placeable cells, and a shallow `searchAdversary` check must not find an obvious thief-forced opening.

This is not a unique-solution generator and it does not record a globally optimal cop strategy. The current guarantees are:

- **Proved easy openings**: easy 11×11 levels are accepted only when search proves a cop win.
- **Honest medium/hard degradation**: bottleneck construction plus shallow checks make large boards playable, without claiming a full global proof.
- **Controllable scale**: difficulty affects board size, cop budget, and openness.
- **Explainable**: every position can emit a BFS path for the education visualization, and AI tier appears in solver stats.

A future stricter version could add finite-horizon minimax / AND-OR search. The related Angel and Devil game should remain a separate module for the infinite-graph escape-versus-blocking theory.
