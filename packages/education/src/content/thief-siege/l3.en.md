# Thief Siege — Escape Paths and Bottlenecks on a Graph

## 1. 玩 · Play

The rules are compact: each turn you place one cop on a walkable cell, then the thief moves one step. Edge exits are the thief's target. If the thief has no route to any exit, the cops win.

The play loop is about reading routes, shrinking space, and creating a trap. The education layer explains what you are already doing; it is not required before play.

## 2. 思考 · Think

A common mistake is to stare only at cells adjacent to the thief. The deeper questions are:

- Among all paths from the thief to the exit set, which one is shortest?
- Which placement lengthens that shortest path or disconnects the exits entirely?
- Why do some cells behave like bridges, changing the whole board when blocked?

These questions turn "surround the thief" into a graph path and cut problem.

## 3. 揭示 · Reveal

### 3.1 Graph Model

Represent the board as an undirected graph $G=(V,E)$:

- $V$: every `floor` and `exit` cell
- $E$: edges between 4-neighbor walkable cells
- $s \in V$: the thief position
- $T \subseteq V$: all exit cells
- $C \subseteq V$: cells occupied by cops

The current walkable graph is $G' = G[V \setminus C]$. The thief can still escape iff there exists a path from $s$ to some $t \in T$ in $G'$.

### 3.2 BFS and the Shortest Escape Path

Because each move has equal cost, BFS expands from $s$ by distance layers. The first reached exit gives the shortest escape length:

$$d(s,T)=\min_{t\in T} d(s,t)$$

If the queue is exhausted without reaching an exit, $s$ and $T$ are disconnected, so the thief is trapped.

### 3.3 Bottleneck Intuition

Placing a cop deletes one vertex. If a cell lies on many paths from $s$ to $T$, it is a bottleneck candidate; blocking it may force long detours or disconnect every route.

The current solver uses an "escape BFS + path-first blocking" heuristic: it recommends legal cells on the current shortest escape path. This is fast and explainable, but it is not a complete minimax solver. It does not enumerate the full game tree of cop placements, thief replies, and future turns.

## 4. 求解 · Solve

Core algorithm:

```
EscapeBFS(state):
  blocked = cops
  queue = [thief]
  parent[thief] = null

  while queue not empty:
    current = dequeue(queue)
    if current is an exit:
      return reconstructPath(parent, current)

    for each 4-neighbor next:
      if next is walkable and next not blocked and next not visited:
        parent[next] = current
        enqueue(next)

  return no escape path
```

The complexity is $O(|V|+|E|)$. On an 11×11 board, there are only around a hundred vertices, so the solver can run synchronously without a Web Worker.

The visualization reads `trace.visualizationData.escapePath` and maps the reconstructed BFS path back onto board cells. Yellow cells show the current shortest escape route, while exits, cops, and the thief keep distinct markers so you can see exactly what a placement blocks.

## 5. 出题 · Create

The generator uses an irregular mask:

1. Pick a size: 7, 9, or 11 depending on the difficulty tier.
2. Generate a playable region from an ellipse with light random wobble; outside cells become obstacles.
3. Mark the playable boundary as `exit`; interior cells become `floor`.
4. Add a few interior obstacles according to difficulty while keeping the center area safe.
5. Place the thief near the center.
6. Run BFS to verify that the initial state has at least one escape path.

This is not a unique-solution generator and it does not record a globally optimal cop strategy. The current guarantees are:

- **Playable**: the initial state has at least one escape route, so the thief is not trapped at spawn.
- **Controllable scale**: difficulty affects board size, cop budget, and openness.
- **Explainable**: every position can emit a BFS path for the education visualization.

A future stricter version could add finite-horizon minimax / AND-OR search. The related Angel and Devil game should remain a separate module for the infinite-graph escape-versus-blocking theory.
