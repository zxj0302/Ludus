# 围堵小偷 — 图上的逃脱路径与瓶颈

## 1. 玩 · Play

规则很短：你每回合放置一名警察，占住一个可通行格；小偷随后移动一步。边缘出口是小偷的目标，无法再走向任何出口时警察获胜。

v1.1 把地图扩到按难度分级的 11×11、15×15、19×19。手感重点仍是“观察路线、压缩空间、制造合围”，但现在你要堵的是未来几轮的逃逸空间，而不只是眼前那条黄色最短路。

## 2. 思考 · Think

一个常见误区是只盯着小偷脚下的相邻格。真正关键的问题是：

- 小偷当前位置到出口集合的所有路径里，哪条最短？
- 放在哪个格子能让最短路变长，甚至让出口不可达？
- 有些格子为什么像桥一样，一堵住就改变整个局面？
- 如果小偷知道你下一轮还会继续堵，它现在应该保最短路、保出口数量，还是保未来分叉？

这些问题把“围堵”转化成了图上的路径、割断与交替博弈问题。

## 3. 揭示 · Reveal

### 3.1 图模型

设棋盘对应无向图 $G=(V,E)$：

- $V$：所有 `floor` 与 `exit` 格子
- $E$：四连通相邻格子之间的边
- $s \in V$：小偷当前位置
- $T \subseteq V$：所有出口格
- $C \subseteq V$：警察占据的格子

当前可走图是 $G' = G[V \setminus C]$。小偷是否还能逃脱，等价于判断 $G'$ 中是否存在从 $s$ 到任意 $t \in T$ 的路径。

### 3.2 BFS 与最短逃脱路

因为每次移动代价相同，BFS 从 $s$ 出发按距离层扩展。第一次访问到出口时，路径长度就是最短步数：

$$d(s,T)=\min_{t\in T} d(s,t)$$

若 BFS 队列耗尽仍未访问出口，则 $s$ 与 $T$ 不连通，小偷被围住。

### 3.3 瓶颈直觉

警察放置可以看成删除一个顶点。若某个格子位于大量从 $s$ 到 $T$ 的路径上，它就是瓶颈候选；堵住它可能让所有可行路径绕远，或直接断开连通性。

v1 只用“逃脱 BFS + 路径优先堵点”启发式。v1.1 加入交替搜索：警察节点枚举 `place`，小偷节点枚举 `step`，警察选择让小偷评价最低的走法，小偷选择让自己评价最高的走法。这就是有限状态追逃博弈上的 minimax 直觉。

### 3.4 对抗搜索口径

完整博弈树会随棋盘尺寸、可放置格和回合数快速膨胀，因此实现采用分层口径：

- **简单 11×11**：生成阶段用较宽预算跑 `copHasWinningStrategy`，只接受能证明警察可胜的开局。
- **中等 15×15 / 困难 19×19**：优先构造瓶颈/单通道形态，再做浅层对抗抽检，拒绝明显会被小偷立即打穿的局面。
- **运行时 AI**：优先对抗搜索；时间或深度耗尽时标记为 `bounded`；拿不到合法对抗步时退回 BFS 贪心。

因此，中/难关的“可围堵”是工程保证，不是“枚举全部未来并给出数学证明”。

## 4. 求解 · Solve

可视化展示的第一层仍是 BFS，因为它最直接：

```text
EscapeBFS(state):
  blocked = cops
  queue = [thief]
  parent[thief] = null

  while queue not empty:
    current = dequeue(queue)
    if current is an exit:
      return reconstructPath(parent, current)

    for each 4-neighbor next:
      if next is walkable and next not blocked and next not visited:
        parent[next] = current
        enqueue(next)

  return no escape path
```

BFS 复杂度为 $O(|V|+|E|)$，用于判断当前是否仍有逃路，并给出 `escape-path` 可视化。

对抗引擎在 BFS 之上做有限深度 alpha-beta：

```text
Search(state, depth, alpha, beta):
  if thief escaped: return +10000
  if thief trapped: return -10000
  if timeout or depth == 0: return Evaluate(state)

  if thief turn:
    choose step with maximum score
  else:
    choose place with minimum score
```

评价函数综合最短逃脱路长度、可达出口数和剩余警察数量。越容易逃，对小偷分数越高；越接近被切断，对警察越有利。

可视化读取 `trace.visualizationData.escapePath`，把 BFS 还原路径映射回棋盘格：黄色表示当前最短逃脱路径，出口、警察、小偷分别保留独立标记，方便对照“这一手到底堵住了什么”。

Web 运行时还注册了 `ai-move` Worker 任务。`thief-siege` 的小偷回合优先在 Worker 中计算，避免 15×15/19×19 搜索阻塞 UI；Worker 不可用时走主线程 `getAIMoveAsync` / 同步回退。求解统计中的 `solverName` 会呈现 `escape-adversary/perfect`、`escape-adversary/bounded` 或 `escape-adversary/bfs`。

## 5. 出题 · Create

生成器采用不规则 mask：

1. 选择尺寸：11、15、19 对应简单、中等、困难。
2. 以椭圆加轻微扰动生成可玩区域，区域外为障碍。
3. 可玩区域边界标记为 `exit`，内部为 `floor`。
4. 根据难度添加少量内部障碍，并保护中心附近可通行。
5. 小偷放在中心附近候选格。
6. 调用 BFS 验证初始状态必须存在逃脱路径。
7. 运行混合 win gate：
   - 简单：`copHasWinningStrategy(state, { maxDepth: Infinity })` 必须为真。
   - 中/难：最短路上必须有足够可放置点，并通过浅层 `searchAdversary` 抽检。

难度不是“唯一解”或“已知最优警察策略”。当前版本的保证是：

- **简单关可证明**：生成器只接受搜索证明警察可胜的 11×11 开局。
- **中/难关诚实降级**：构造瓶颈 + 浅层抽检，保证不像随机大图那样松散，但不声称全局完美证明。
- **可控规模**：难度档影响棋盘尺寸、警察预算和开放程度。
- **可解释性**：每个局面都能输出 BFS 路径用于教学可视化，AI 档位可通过求解统计观察。

未来如果要做更严格的“最优围堵”，可以把它扩展为有限回合 minimax / AND-OR 搜索，或另开 Angel and Devil 模块研究无限图上的逃逸与围堵问题。
