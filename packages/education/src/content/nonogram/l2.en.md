## 1. Play

Each row and column has a set of number clues. Each number represents a **consecutive run of filled cells**. Your task: deduce which cells to fill based on the clues.

- **Left click**: Fill a cell (or unfill)
- **Right click / Shift+click**: Mark as empty (cross)
- **Arrow keys**: Move cursor; **Space**: Fill; **X**: Mark empty

Clue example: `[3, 1]` means "a run of 3 filled cells, then at least 1 empty, then a run of 1 filled cell."

> 💡 Tip: Start with the largest clue numbers — they're often the breakthrough!

## 2. Think

> Given row and column clues, how do you determine which cells MUST be filled and which MUST be empty?

Try this: a 5-cell row with clue `[5]`. Obviously the entire row is filled.

What about clue `[2, 1]` on a length-5 row? Enumerate all valid arrangements — you'll discover some positions are filled in EVERY valid arrangement.

- Clue `[3]` on length 5: which positions are **definitely** filled?
- Dense clues like `[2, 2]` on length 5: what can you determine?
- Sparse clues like `[1, 1]` on length 5: what can you determine?

## 3. Reveal

### Problem Definition

**Nonogram (Picross / Griddlers / Paint by Numbers)**:

> Given an N×M grid with row and column number clues, determine which cells to fill so that the consecutive filled runs in each row/column match the clue numbers.

### Complexity

| Variant | Class | Notes |
|---------|-------|-------|
| Decision (solution exists?) | **NP-complete** | Proved by Ueda & Nagao (1996) |
| Find one solution | NP-hard | Backtracking search, worst-case exponential |
| Uniqueness check | co-NP-hard | Requires solution counting |

> 📘 Category: **§4 Constraint Satisfaction (CSP)**. Nonogram is Ludus's first NP-complete game.

### Line Solving (Deterministic Constraint Propagation)

The core strategy: look at one row/column independently, enumerate all possible fill arrangements, find cells that are "filled in all" or "empty in all":

```
Algorithm solveLine(line, clues):
  Enumerate all valid arrangements for this line
  Filter: keep only those compatible with known cells
  Merge: cells filled in ALL arrangements → definitely filled
         cells empty in ALL arrangements → definitely empty
```

Iterate over all rows and columns until no new information. Most easy puzzles are solved by line solving alone.

### Backtracking Search

When line solving stalls:

1. Pick the most constrained undetermined cell
2. Try "fill" → line solve propagation → backtrack on contradiction
3. Try "empty" → line solve propagation → backtrack on contradiction
4. Only one branch survives → confirm the cell's value

### Difficulty Tiers

| Tier | Score | Grid Size | Line-Solve Ratio | Backtracking Needed |
|------|-------|-----------|-----------------|-------------------|
| Easy | 1–33 | 5×5 ~ 8×8 | >80% | Rarely |
| Medium | 34–66 | 8×8 ~ 12×12 | 50–80% | Sometimes |
| Hard | 67–100 | 12×12 ~ 20×20 | <50% | Often |

## 4. Solve

The solver uses a two-layer **line solver + backtracking** architecture:

1. **Layer 1 — Line solving iteration**: Apply solveLine to all rows and columns alternately until convergence
2. **Layer 2 — Backtracking search**: Branch on undetermined cells, re-applying line solving after each guess

Solution counting uses the same algorithm but counts up to a limit. Uniqueness verification: `countSolutions(puzzle, 2) === 1`.

## 5. Create

The level generator provides three guarantees:

- **Solvability**: Generate a random pattern → compute clues → at least one solution exists (the original pattern)
- **Unique solution (guaranteed)**: Verify `countSolutions(puzzle, 2) === 1`. Non-unique puzzles are rejected. Note: solution counting may be slow for large grids (15×15+); heuristics help select promising candidates
- **Controllable difficulty**: Grid size ranges (Easy 5–8 / Medium 8–12 / Hard 12–20); fill density affects clue sparsity
