## 3. Reveal

### §3.1 Formal Definition

**Nonogram (Picross / Griddlers)**:

- **Input**: N×M grid, row clues R = [r₁, ..., rₙ] (rᵢ = [a₁, a₂, ...] — consecutive filled run lengths for row i), column clues C = [c₁, ..., cₘ]
- **State**: N×M matrix, each cell ∈ {unknown, filled, empty}
- **Goal**: Fill cells so that each row/column's consecutive filled runs exactly match the clue numbers
- **Optimization**: Usually just finding a feasible solution (Nonogram is a satisfaction problem, not optimization)

### §3.2 Complexity Classification

| Variant | Class | Proof |
|---------|-------|-------|
| Decision (solution exists?) | **NP-complete** | Ueda & Nagao, 1996 — reduction from 3-SAT |
| Find one solution | NP-hard | Search space O(2^(N×M)), worst-case exponential |
| Uniqueness check | co-NP-hard | Solution counting → USAT reduction |

> 📘 Category: **§4 Constraint Satisfaction (CSP)**. Nonogram is a painting game hiding an NP-complete problem.

**Why NP-complete?**

Intuition: each cell's fill/empty choice is a Boolean variable; row and column clues form constraints. These intersecting constraints create a network resembling 3-SAT logic. The proof sketch: given any 3-CNF formula φ, construct a corresponding Nonogram instance; φ is satisfiable ⇔ Nonogram has a solution; solutions are verifiable in polynomial time.

### §3.3 Line Solving Algorithm

#### Enumeration Method

For a length-L line with clues [c₁, ..., cₖ], all valid arrangements satisfy:

1. k consecutive filled blocks of lengths c₁, ..., cₖ
2. At least one gap between blocks (k−1 gaps total)
3. Optional empty cells at ends

**Recursive enumeration**:

```
function generatePlacements(L, clues):
  if clues is empty: return [all-false array of length L]

  blockSize = clues[0]
  remainingBlocks = clues[1:]
  remainingMin = sum(remainingBlocks) + length(remainingBlocks)  // blocks + gaps

  for startPos in 0 .. L - blockSize - remainingMin:
    placement = [false repeated startPos times]
    placement += [true repeated blockSize times]
    if remainingBlocks is not empty: placement += [false]  // gap

    subPlacements = generatePlacements(L - placement.length, remainingBlocks)
    for each sub in subPlacements:
      yield placement + sub
```

#### Merge (Intersection)

```
function solveLine(line, clues):
  placements = generatePlacements(line.length, clues)
  valid = placements.filter(p => compatible(p, line))
  if valid is empty: return CONTRADICTION

  merged = []
  for i in 0..line.length-1:
    if line[i] is known: merged[i] = line[i]
    else if all valid have p[i]==true:  merged[i] = FILLED
    else if all valid have p[i]==false: merged[i] = EMPTY
    else: merged[i] = UNKNOWN
  return merged
```

#### Iterative Propagation

```
function lineSolve(grid, rowClues, colClues):
  queue = all rows + all columns
  while queue not empty:
    line = queue.dequeue()
    result = solveLine(line, clues)
    if result is CONTRADICTION: return FAIL
    if result changed cells:
      update grid
      enqueue all intersecting lines
  return grid
```

**Correctness**: Line solving is monotonic — cells only go from unknown to determined, never reverting. Iteration must converge (finite state space).

### §3.4 Backtracking Search

When line solving converges but not all cells are determined:

```
function solve(grid, rowClues, colClues, limit):
  // Phase 1: Line solving
  grid = lineSolve(grid, rowClues, colClues)
  if all cells determined and consistent: return SOLUTION

  // Phase 2: Pick most constrained cell
  cell = pickCell(grid)  // prefer cell with most known neighbors

  // Branch 1: Fill
  grid[cell] = FILLED
  result = solve(grid, clues, limit)
  if result found: return result

  // Branch 2: Empty
  grid[cell] = EMPTY
  result = solve(grid, clues, limit)
  return result
```

**Key optimizations**:
- **MRV heuristic**: Pick the cell in the row/column with the most known cells (most constrained first)
- **Forward checking**: Re-run line solving after each guess to detect contradictions early
- **Solution count limit**: `countSolutions(puzzle, 2)` — stop at 2, dramatically accelerating uniqueness verification

### §3.5 Difficulty Factor Analysis

Four-factor decomposition:

| Factor | Weight | Formula | Rationale |
|--------|--------|---------|-----------|
| Grid size | 0–40 | `(cells-25)/(400-25)×40` | 5×5→0, 20×20→40 |
| Line-solve ratio | 0–30 | `(1-lineSolveRatio)×30` | Lower ratio → more backtracking needed |
| Max backtrack depth | 0–20 | `min(maxDepth/20,1)×20` | Deeper search → harder |
| Clue density | 0–10 | `(1-totalClues/(2(w+h)))×10` | Fewer clues → less information |

Difficulty = min(sum of four, 100)

## 4. Solve

### §4.1 Complete Solver Pseudocode

```
Algorithm solveNonogram(state):
  Input:  NonogramState with rowClues, colClues
  Output: solution grid or "unsolvable"

  // Phase 1: Line solve all rows and columns
  queue = all rows ∪ all columns
  while queue is not empty:
    line = queue.dequeue()
    result = solveLine(line, clues[line])
    if result == contradiction: mark inconsistent
    if result changed: enqueue intersecting lines

  // Phase 2: Branch if needed
  if all cells determined: return grid as solution

  cell = pickMostConstrainedCell()
  for value in [FILLED, EMPTY]:
    grid[cell] = value
    result = solveNonogram(updatedGrid)
    if result found: return result

  return UNSOLVABLE
```

### §4.2 Correctness

- **Line solving**: Based on enumeration and intersection — mathematically exact
- **Backtracking**: Complete — tries all possible branches (exhaustive search)
- **Optimality**: Nonogram has no optimization objective; any feasible solution works

### §4.3 Solver Method Comparison

| Method | Pros | Cons | Use Case |
|--------|------|------|----------|
| **Pure line solving** | O(w×h×2^max(w,h)) per round, deterministic | Cannot solve all puzzles | Simple puzzles (~70%) |
| **Line + backtracking** (this impl) | Complete, MRV heuristic speeds search | Worst-case exponential | All sizes |
| ILP (Integer Linear Programming) | Mature solvers available | External dependency, opaque | Large industrial puzzles |
| Neural approaches | Interesting research direction | No correctness guarantee | Academic research |

## 5. Create

### §5.1 Generation Flow

```
Algorithm generateNonogramLevel(difficultyRange):
  1. Select grid size from difficulty range (Easy 5-8 / Med 8-12 / Hard 12-20)
  2. Generate random filled pattern (rectangular blocks + noise, 40-60% density)
  3. Compute row/column clues from the pattern
  4. Verify unique solution: countSolutions(puzzle, 2) === 1
  5. Use solver to get line-solve ratio + backtrack depth
  6. Compute difficulty score → reject if outside requested range
  7. After 100 attempts, fall back to best candidate
```

### §5.2 Unique Solution Guarantee

- `countSolutions(limit=2)`: stop searching as soon as second solution is found
- For grids ≤ 10×10, solution counting completes in seconds
- For grids ≥ 15×15, counting may take seconds to tens of seconds
- Generator falls back to smaller grids or simpler patterns if too slow
- Future: add timeout — if counting doesn't finish in 5s, treat as "unverified", fall back

Note: Nonogram solution counting is worst-case exponential. In practice, heuristics (forward checking, MRV branching) dramatically reduce the search space. For most generated puzzles (40-60% density), counting finishes quickly — either the unique solution is found fast or multiple solutions are discovered early.

### §5.3 Controllable Difficulty

Three difficulty levers:

1. **Grid size** (strongest): 5×5 → 20×20, state space grows from 25 to 400 variables
2. **Fill density**: Extreme densities (very sparse or very dense) are easier; moderate density (40-60%) is hardest
3. **Pattern structure**: Block-structured patterns produce more unique-solution puzzles than pure noise

### §5.4 Verification Checklist

Every generated level passes:

- [x] Pattern is non-trivial (at least some filled and empty rows)
- [x] Computed clues match the pattern
- [x] `countSolutions(puzzle, 2) === 1` (unique solution)
- [x] Difficulty score in requested range (or recorded as best candidate)
- [x] Grid size ≥ 5×5
