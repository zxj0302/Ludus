## 3. 揭示 · Reveal

### §3.1 形式化定义

**Nonogram（ノノグラム / Picross）**：

- **输入**：N 行 M 列网格，行线索 R = [r₁, ..., rₙ]（其中 rᵢ = [a₁, a₂, ...] 为第 i 行的连续填充段长度），列线索 C = [c₁, ..., cₘ]（同理）
- **状态**：N×M 矩阵，每格 ∈ {未知, 填充, 空格}
- **目标**：找到一种填充方案，使得每行/每列的连续填充段长度序列恰好等于该行/列的线索
- **优化目标**：通常只需找到一个可行解（Nonogram 不是优化问题）

### §3.2 复杂度归类

| 问题变体 | 复杂度 | 证明 |
|---------|--------|------|
| 判定（是否存在解） | **NP-complete** | Ueda & Nagao, 1996 — 通过 3-SAT 归约 |
| 寻找一个解 | NP-hard | 搜索空间 O(2^(N×M))，最坏指数 |
| 唯一性判定 | co-NP-hard | 解计数 → USAT 归约 |

> 📘 属于 **§4 约束满足 (CSP)** 领域。Noogram 是一款伪装成绘画游戏的 NP-complete 问题。

**为什么 Nonogram 是 NP-complete？**

直观原因：每个格子的「填/不填」选择构成了 N×M 个布尔变量，行线索和列线索构成了约束。这些约束相互交叉，形成类似 3-SAT 的逻辑约束网络。证明思路：
1. 任给 3-CNF 公式 φ，构造对应 Nonogram 实例
2. φ 可满足 ⇔ Nonogram 有解
3. Nonogram 解可被多项式时间验证

这解释了为什么大 Nonogram 的求解器需要回溯搜索。

### §3.3 线求解算法

#### 枚举法

对长度为 L 的行，线索为 [c₁, ..., cₖ]，所有合法排列满足：

1. k 段连续填充段，长度依次为 c₁, ..., cₖ
2. 段之间至少有一个空格（共 k−1 个间隙）
3. 首尾可选空格

**递归枚举**：

```
function generatePlacements(L, clues):
  if clues is empty: return [all-false array of length L]

  blockSize = clues[0]
  remainingBlocks = clues[1:]
  remainingMin = sum(remainingBlocks) + length(remainingBlocks)  // blocks + gaps

  for startPos in 0 .. L - blockSize - remainingMin:
    placement = [false repeated startPos times]
    placement += [true repeated blockSize times]
    if remainingBlocks is not empty: placement += [false]  // gap

    subPlacements = generatePlacements(L - placement.length, remainingBlocks)
    for each sub in subPlacements:
      yield placement + sub
```

#### 合并（取交集）

```
function solveLine(line, clues):
  placements = generatePlacements(line.length, clues)
  valid = placements.filter(p => compatible(p, line))
  if valid is empty: return CONTRADICTION

  merged = []
  for i in 0..line.length-1:
    if line[i] is known: merged[i] = line[i]
    else if all valid have p[i]==true:  merged[i] = FILLED
    else if all valid have p[i]==false: merged[i] = EMPTY
    else: merged[i] = UNKNOWN
  return merged
```

#### 迭代传播

```
function lineSolve(grid, rowClues, colClues):
  queue = all rows + all columns
  while queue not empty:
    line = queue.dequeue()
    result = solveLine(line, clues)
    if result is CONTRADICTION: return FAIL
    if result changed cells:
      update grid
      enqueue all intersecting lines
  return grid
```

**正确性**：线求解是单调的——格子只会从「未知」变为「确定」，从不回退。迭代必然收敛（状态数有限）。

### §3.4 回溯搜索

当线求解收敛但并非所有格子都确定时：

```
function solve(grid, rowClues, colClues, limit):
  // Phase 1: Line solving
  grid = lineSolve(grid, rowClues, colClues)
  if all cells determined and consistent: return SOLUTION

  // Phase 2: Pick most constrained cell
  cell = pickCell(grid)  // prefer cell with most known neighbors

  // Branch 1: Fill
  grid[cell] = FILLED
  result = solve(grid, clues, limit)
  if result found: return result

  // Branch 2: Empty
  grid[cell] = EMPTY
  result = solve(grid, clues, limit)
  return result
```

**关键优化**：
- **MRV 启发式**（Most Constrained Variable）：优先选择约束最多的格子（所在行列已知格子最多的）
- **前向检查**：每次分支后立即做线求解，提前发现矛盾
- **解计数上限**：`countSolutions(puzzle, 2)` — 数到 2 立即返回，大幅加速唯一性验证

### §3.5 难度因素分析

四因素分解：

| 因素 | 权重 | 公式 | 说明 |
|------|------|------|------|
| 网格大小 | 0–40 | `(cells-25)/(400-25)×40` | 5×5→0, 20×20→40 |
| 线求解覆盖率 | 0–30 | `(1-lineSolveRatio)×30` | 线求解确定的比例越低，需要的回溯越多 |
| 最大回溯深度 | 0–20 | `min(maxDepth/20,1)×20` | 回溯越深越难 |
| 线索密度 | 0–10 | `(1-totalClues/(2(w+h)))×10` | 线索越少信息越少 |

难度 = min(四项之和, 100)

## 4. 求解 · Solve

### §4.1 完整求解器伪代码

```
Algorithm solveNonogram(state):
  Input:  NonogramState with rowClues, colClues
  Output: solution grid or "unsolvable"

  // Phase 1: Line solve all rows and columns
  queue = all rows ∪ all columns
  while queue is not empty:
    line = queue.dequeue()
    result = solveLine(line, clues[line])
    if result == contradiction: mark inconsistent
    if result changed: enqueue intersecting lines

  // Phase 2: Branch if needed
  if all cells determined: return grid as solution

  cell = pickMostConstrainedCell()
  for value in [FILLED, EMPTY]:
    grid[cell] = value
    result = solveNonogram(updatedGrid)
    if result found: return result

  return UNSOLVABLE
```

### §4.2 正确性

- **线求解**：基于枚举取交集，数学上精确——任何合法解都必须满足交集中的约束
- **回溯搜索**：完备——尝试所有可能分支（穷举搜索空间）
- **优解性**：Nonogram 不涉及优化目标，找到任意可行解即可

### §4.3 求解方法对比

| 方法 | 优点 | 缺点 | 适用 |
|------|------|------|------|
| **纯线求解** | O(w×h×2^max(w,h)) 每轮，确定性强 | 不能解所有谜题 | 简单谜题 (~70%) |
| **线求解 + 回溯**（本实现） | 完备，MRV 启发式加速 | 最坏指数时间 | 所有尺寸 |
| ILP（整数线性规划） | 成熟求解器可用 | 依赖外部库，不透明 | 大工业级谜题 |
| 神经网络方法 | 有趣的研究方向 | 不保证正确性 | 学术研究 |

## 5. 出题 · Create

### §5.1 生成流程

```
Algorithm generateNonogramLevel(difficultyRange):
  1. 根据难度范围选网格大小（Easy 5-8 / Med 8-12 / Hard 12-20）
  2. 随机生成填充图案（矩形块 + 随机噪点，密度 40-60%）
  3. 从图案计算行列线索
  4. 验证唯一解：countSolutions(puzzle, 2) === 1
  5. 用求解器获取线求解覆盖率 + 回溯深度
  6. 计算难度分数 → 若不在范围内，拒绝并重试
  7. 100 次尝试后回退到最佳候选
```

### §5.2 唯一解保证

- `countSolutions(limit=2)`：当找到第二个解时立即停止搜索
- 对于 10×10 以下网格，解计数在秒级内完成
- 对于 15×15+ 网格，解计数可能需要数秒至数十秒
- 如果超过合理时间，生成器回退到较小网格或更简单的图案
- 未来可加超时机制：如果 5 秒内未完成计数，视为「未验证」，回退

注意：Nonogram 的解计数在最坏情况下是指数级的。实际中的启发式方法（如前向检查、MRV 分支）大大减少了搜索空间。对于大多数实际生成的谜题（密度 40-60%），解计数通常很快结束（要么快速找到唯一解，要么快速发现多个解）。

### §5.3 难度可控

难度通过以下杠杆调节：

1. **网格大小**（最强杠杆）：5×5 → 20×20，状态空间从 25 个变量变为 400 个
2. **填充密度**：极低或极高密度都更容易（线索更确定），中等密度（40-60%）最难
3. **图案结构**：随机块状图案比纯随机噪声更容易生成唯一解的谜题

### §5.4 验证清单

每个生成的关卡通过以下验证：

- [x] 图案非平凡（至少有一些填充和空行）
- [x] 从图案计算的线索与图案一致
- [x] `countSolutions(puzzle, 2) === 1`（唯一解）
- [x] 难度分数在请求范围内（或记录为最佳候选）
- [x] 网格尺寸 ≥ 5×5
