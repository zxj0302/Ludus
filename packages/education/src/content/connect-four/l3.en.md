# Connect Four — Minimax / Alpha-Beta

## 1. Play

Connect Four is played on a 6×7 grid. Players drop discs into columns; discs fall to the lowest empty cell. First to connect **four in a row** (horizontal, vertical, or diagonal) wins; a full board with no four-in-a-row is a draw.

This Hub build is **human vs AI**: choose who moves first, then play. The AI uses **depth-limited Alpha-Beta** (not the full Allis opening book).

## 2. Think

- If the opponent threatens four next turn, which column must you block? Can one pass detect win/block?
- Minimax assumes perfect play; with depth 6, what mistakes appear?
- Alpha-Beta matches Minimax’s result—why far fewer nodes?
- 7×6 is strongly solved (first player wins)—how does that differ from our honest but shallow AI?

## 3. Reveal

### 3.1 Formal model

**State** $s$: board $B \in \{0,1,2\}^{6 \times 7}$ (empty / player / AI), plus `currentPlayer`, `phase ∈ {choosing, playing}`, and `playerStarts`.

**Action**: pick a non-full column $c$; disc falls to the bottom empty cell.

**Terminal**: four-in-a-row for either side, or draw when full.

### 3.2 Minimax

```text
minimax(s, depth, maximizing):
  if terminal(s) or depth=0: return eval(s)
  if maximizing:
    return max_a minimax(apply(s,a), depth-1, false)
  else:
    return min_a minimax(apply(s,a), depth-1, true)
```

At `depth=0`, Hub uses a **center-column heuristic**; terminals use ±WIN_SCORE.

### 3.3 Alpha-Beta pruning

Maintain $[\alpha, \beta]$. Max layer: prune when value $\ge \beta$; Min layer: prune when value $\le \alpha$. Pruned branches cannot change the root optimum.

See `packages/games/src/connect-four/solver.ts`; `findTacticalMove` handles instant wins/blocks before search.

### 3.4 Complexity

- **Game complexity**: PSPACE-complete in general.
- **Search tree**: branching $\le 7$, depth $\le 42$; still exponential—depth and time caps required.
- **Strong solution**: Allis (1988) proved **first-player win** on 7×6; perfect play ends on move **41**. See **Solve** below for outcomes and references.

## 4. Solve

### 4.1 Solver pipeline

1. `findTacticalMove`: immediate win or block-four.
2. `searchBestMove`: Alpha-Beta (default `maxDepth=8`, ~4.5s; Worker can go deeper).
3. `solveConnectFour`: simulates optimal alternating play; emits `minimax-tree` trace and `playerStarts`.

AI moves run in a Web Worker to keep the UI responsive.

### 4.2 UI contract

- `GamePlugin.ai.isPlayerVictory`: victory sound only when `winner === 0`.
- Live Analysis skips full-game simulation while `phase === choosing`.

### 4.3 7×6 perfect play & sides

On the standard 7×6 board, optimal play is **strongly solved** ([Christophe Steininger c4](https://github.com/ChristopheSteininger/c4) tables):

| Item | Result |
|------|--------|
| Perfect-play outcome | **First player wins** (1st) |
| Perfect game length | Ends on move **41** |

**Choosing sides:**

- **I go first** (`playerStarts = true`): with perfect play you move first and can theoretically force a win.
- **AI goes first** (`playerStarts = false`): with perfect play the AI moves first and can theoretically force a win.

Our solver is **depth-limited** Alpha-Beta—it simulates mutual optimality within the search cap, **not** an Allis / Tromp / c4 strong-solution book. Sidebar traces are for teaching only.

## 5. Create

`generateConnectFourLevel` **always** returns:

- Empty 6×7 board;
- `phase: 'choosing'` (pick sides);
- Difficulty score from `seed` sets `aiMaxDepth` (easy 4 / medium 6 / hard 9)—**does not** alter the opening position.

New level / seed = fresh empty board; `playerStarts` and move history define the actual game.
