## 1. Play

Professionally, Peg Solitaire is a tiny irreversible machine: every move removes one peg, so mistakes cannot be undone by shuttling pieces around.

**Hook 1: garbage collection without an undo stack.** You want one survivor, but each collection step may delete a future bridge.

This build locks the English 33-hole board. **Playable goals are only:**

- `one-any`: exactly one peg, anywhere.
- `one-center`: exactly one peg, and it must sit in the center hole (index 16).

The toolbar browses by **mode**: leave-one vs center-one (including classic center-vacant). The historical relaxed goal `le3` (≤3 pegs) is **not** offered in play — education-only footnote.

**Rigorous claim 1: any legal route from $n$ pegs to $k$ pegs has length $n-k$.** Classic center-vacant (32 pegs) to a singleton ⇒ exactly 31 single jumps. Bergholt’s “18 moves” counts multi-jumps; do not conflate the two optimality statements.

## 2. Think

Local legality is easy; global reachability is not.

**Hook 2: emptier can be harder.** Branching factor is not monotone in peg count.

Three analysis layers:

1. **Counting:** remaining pegs ⇒ minimum remaining jumps.
2. **Bridges:** need an orthogonal `from-over-to` triple.
3. **Goals:** `one-center` is stricter than `one-any` because the accepting set is a singleton, not the union of all singletons.

**Rigorous claim 2: the legal-move graph is a DAG stratified by `popcount`.** Visited sets / D4 keys merge alternate routes and symmetric copies; they are not cycle guards.

**Hook 3: D4 is “eight selfies of the same person.”**

Goal contrast (required reading):

- `one-any` accepts any singleton bitmask.
- `one-center` accepts only the center singleton.
- The cultural classic start aims at the latter; textbooks note the final singleton often can finish center or edge-center — community/textbook tier, not a new proof from this solver.

## 3. Reveal

### 3.1 Bitmasks

Thirty-three holes fit in one JS `number`. Hole $i$ is occupied iff $\lfloor B/2^i\rfloor \bmod 2 = 1$.

### 3.2 Symmetry

D4 acts on board coordinates; `canonicalKey` takes the minimum image. For `one-center` the center is fixed, so pruning remains sound; for `one-any`, singleton terminals are symmetry-related and pruning still preserves reachability conclusions.

### 3.3 Complexity intuition

Generalized peg-solitaire variants can be hard; “the English classic is solvable” does **not** imply “every residual is poly-time.”

## 4. Solver

### 4.1 What this repo actually runs

- Shallow / `findShortest`: **BFS + D4** (level-order shortest paths; for singleton goals the length is already $n-1$, so BFS’s main win is a quick path on small boards).
- Deep default: **DFS + D4 + time budget** (find **any** reachable route first; timeouts are honest).
- Worker keeps the UI responsive.

Visualization: React Flow **sampled search tree** (amber principal variation + capped grey side branches) plus explore stats — not a full state-space certificate.

### 4.2 Why “more efficient” is not just a fancier shortest-path search

For singleton goals every legal single-jump solution has the **same length** ($n-1$). A* / IDA* with a peg-count heuristic mostly collapses to “search at a known depth” — the bottleneck is pruning and reachability.

Common accelerations in the literature:

| Technique | Role | This repo |
|-----------|------|-----------|
| Bitmask / bitboard | Compact state, fast moves | ✅ |
| D4 canonicalization | Merge rotations / reflections | ✅ |
| Time budget + Worker | Responsive UI, honest timeout | ✅ |
| Pagoda / resource-counting invariants | Cut doomed branches early | ❌ not shipped (L3 extension) |
| Retrograde from the goal set | Strong when acceptors are few | ❌ not shipped |
| Stored classic solutions | Replay a known 31-jump line | Catalog stores `knownSolutionLength`; runtime may still search |

The full 32→1 classic board may time out in the browser budget — an honest product boundary, not a claim that faster solvers do not exist. Stronger proving engines (heavy pruning / retrograde / solution libraries) are out of scope for v1.2.

Catalog length 31 is the single-jump literature count — **not** “this run re-proved optimality.”

## 5. Create

**There is no procedural generator.** Selection mirrors Sokoban: mode + named levels; `generateLevel` is only a Hub first-load fallback (default one-center shelf).

- `generatedBy: 'classic-catalog'`
- `uniqueSolution: false`
- Each entry has `id`, provenance, goal, and optional known length; `tier` is legacy metadata (UI no longer shelves by difficulty)

Out of scope for v1.2: French boards, unique-shortest certificates, full parent/child tree dumps.

**Contrast with Lights Out:** Lights Out is GF(2) linear algebra; Peg Solitaire is state-space search. Do not describe catalog verification as the same algebraic object.
