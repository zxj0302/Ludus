# Euclid's Game — Full Mathematics and Algorithms

## 1. Play

**Euclid's Game (subtraction-multiple variant)** is a two-pile, perfect-information, deterministic **impartial** game. A state is an ordered pair $(a,b)$ with $a \ge b \ge 0$.

Legal move: pick integer $k$ with $1 \le k \le \lfloor a/b \rfloor$ and set $a' = a - kb$. If $a'=0$, the current player **wins immediately**; otherwise the new state is $\text{normalize}(a', b)$.

**Hub terminal semantics (unlike Nim):**

- Win by clearing the larger pile — not by leaving a pure $(0,0)$ “no moves” terminal in the Nim sense.
- The winner **keeps** `currentPlayer` (no toggle), so `isPlayerVictory` can read “human just won”.
- Hand choice uses `phase: 'choosing'`, same as Nim.

## 2. Think

### 2.1 Questions

- How can we classify P/N positions without building the full game tree?
- How do subtraction moves relate to the Euclidean algorithm for $\gcd(a,b)$?
- How should the generator shape difficulty (P-density vs pile sizes)?
- How should hand-choice hints align with P/N?

### 2.2 Intuition

Every legal move peels copies of the smaller pile off the larger one. When the ratio $a/b$ sits near integer landmarks tied to $\varphi$, **every** choice of $k$ improves the opponent's outlook — a P-position.

## 3. Reveal

### 3.1 Formal definitions

**Definition 1 (position)**: $S = \{(a,b) \in \mathbb{N}^2 \mid a \ge b \ge 0\}$ (playable when $b>0$).

**Definition 2 (legal move)**: From $(a,b)$ with $a \ge b > 0$, move $(a,b) \xrightarrow{k} \text{normalize}(a-kb, b)$ for $k \in \{1,\ldots,\lfloor a/b \rfloor\}$; if $a-kb=0$ the current player wins instantly.

**Definition 3 (P / N for this variant)**:

- A move that clears the larger pile is an **instant win** (N for the mover).
- Position $p$ is **N** iff some legal move reaches a P-position or wins instantly.
- Position $p$ is **P** iff every legal move reaches an N-position (and none wins instantly).

> Do not copy Nim’s slogan “terminal = P (no moves)”: here the player who just cleared the larger pile has already won.

### 3.2 φ losing-position theorem (implementation)

Let $\varphi = (1+\sqrt{5})/2$. For $a > b > 0$:

$$p \text{ is a P-position} \iff \lfloor b\varphi \rfloor \ge a \;\wedge\; a < b\varphi$$

**Note**: when $a=b>0$, taking $k=1$ wins immediately → **N**, not P.

This module uses the **subtraction-multiple** ruleset, not the one-step modular variant $(b, a \bmod b)$. Some expositions omit the closed endpoint of the floor inequality; this repo follows code + brute-force cross-checks.

### 3.3 Link to gcd / sibling games

| | Nim | Wythoff | Euclid's Game (this module) |
|--|-----|---------|-----------------------------|
| Invariant | XOR | Beatty / $\varphi$ | $\varphi$ band + gcd structure |
| Moves | remove from one pile | one pile or equal from both | subtract $k\times$ smaller from larger |
| P-test | nim-sum $=0$ | $a=\lfloor k\varphi\rfloor$ | $\lfloor b\varphi\rfloor\ge a < b\varphi$ |

Modular Euclidean steps correspond to particular choices of $k$ in the subtraction game. Ludus uses the cut-the-knot **φ inequality** for O(1) tests, cross-checked by memoized minimax for $a,b \le 12$.

## 4. Solve

### 4.1 `isPPosition` / `findWinningMove`

```typescript
// packages/games/src/euclids-game/solver.ts
const [larger, smaller] = normalizePiles(a, b);
if (larger === smaller) return false; // N: take all in one move
const floorBound = Math.floor(smaller * PHI);
return larger <= floorBound && larger < PHI * smaller;
```

Enumerate $k = 1 \ldots \lfloor a/b \rfloor$: instant win, or land on a P-position → winning move.

### 4.2 Full sequence and hand choice

`solveEuclidsGame` **mirrors Nim**: simulate alternating perfect play and return the full `moves` list.

- In `choosing`: `playerStarts = !isPPosition(piles)` (N → human first; P → AI first).
- `visualizationData.playerStarts` drives Hub hint highlights and education move labels.
- Sidebar “optimal solution” length = human moves in the sequence (`solutionLength`).

### 4.3 Complexity

| Operation | Complexity |
|-----------|------------|
| P/N test | $O(1)$ |
| One winning move | $O(a/b)$ |
| Full simulation | $O(\text{depth} \times a/b)$, depth $\sim O(\log b)$ |

**AI**: prefer `findWinningMove`; else uniform random legal $k$.

## 5. Create

`generateEuclidsGameLevel` (`packages/games/src/euclids-game/generator.ts`):

1. `resolveSeed(config)` → Mulberry32 PRNG
2. Sample $(a,b)$ from `difficultyRange`, enforcing $a > b \ge 2$
3. `preferPPosition`: harder bands bias toward P, easier toward N (up to 24 resamples)
4. Return `phase: 'choosing'` plus `initialPiles`; `generatedBy` is `n-position-bias` or `p-position-bias` (Hub i18n keys wired)

Difficulty score via `computeEuclidsDifficulty`: pile magnitude + P penalty + first-player adjustment.
