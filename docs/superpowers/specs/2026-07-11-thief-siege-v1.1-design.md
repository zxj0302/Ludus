# 围堵小偷 v1.1 — 大地图 + 对抗 AI + 可解保证

> 状态：**已确认**  
> 日期：2026-07-11  
> 前置：`docs/superpowers/specs/2026-07-10-thief-siege-design.md`（v1 已实现）  
> 方案：双引擎分层（用户确认 A）

## 1. 动机

v1 垂直切片可玩，但存在两类体验问题：

1. **地图过小**：生成尺寸锁定在 `{7,9,11}`，可走格偏少，围堵手感局促。
2. **AI 过弱**：小偷仅用贪心 BFS（踏 exit → 最短逃逸下一步 → 保可达），不考虑警察后续堵路，不是真正的交替博弈。

同时产品要求：**在用户适当操作下，开局必须保证警察可胜**（与「开局小偷仍有逃路」同时成立）。

## 2. 已确认决策

| 项 | 结论 |
|----|------|
| 地图 | 按难度分级：易 11 / 中 15 / 难 19 |
| 可解保证 | 混合：易严格对抗验证；中/难构造式 + 浅层抽检 |
| 小偷 AI | 尽量完美；Worker（可并行分片）；超时降级 |
| 总体路线 | 方案 A — 双引擎分层 |
| 非目标 | 六边形、Angel and Devil、警察移动、中/难全局完美证明 |

## 3. 难度 × 地图尺寸

| 难度档 | `difficultyRange` | 网格边长 `n` | 目标可走格（不规则后） | `maxCops` |
|--------|-------------------|--------------|------------------------|-----------|
| 易 | 1–33 | **11** | ~40–70 | 偏高（更好围） |
| 中 | 34–66 | **15** | ~80–140 | 中等 |
| 难 | 67–100 | **19** | ~150–250 | 偏低（更难围） |

规则：

- 允许尺寸集合由 `{7,9,11}` 改为 **`{11,15,19}`**；`config.size` 钳到该集合。
- 仍用椭圆/噪声不规则轮廓；外 = `obstacle`，边缘可走 = `exit`，内部 = `floor`。
- 开局：小偷在内部 `floor`；`phase = 'cop'`；`cops = []`；至少一条到 exit 的路径。

## 4. 生成器：警察必胜保证（混合）

### 4.1 共同前置

1. 障碍洒点后小偷仍可达 ≥1 个 exit。  
2. 有界重试；耗尽则回退到「已知可解」构造模板（仍匹配当前尺寸档）。  
3. 种子可复现（`mulberry32` / `resolveSeed`）。

### 4.2 易（11）— 严格验证

- 在 Worker 中对候选跑交替博弈搜索（警察最大化困住，小偷最大化逃出）。
- 仅当 `copHasWinningStrategy === true` 时接受。
- 超时或未证出 → 丢弃重试；**不放行未证明关卡**。

### 4.3 中（15）— 构造 + 浅层抽检

- 优先瓶颈/少出口/走廊形态；`maxCops` ≥ 切断逃逸的启发式下界（最短逃逸路上可放置点数 / 近似最小割）。
- 浅层对抗抽检（有限深度：警察若干步 + 小偷最优回应）；失败重试。
- 不承诺全树证明；拒绝明显「小偷必逃」开局。

### 4.4 难（19）— 更强构造 + 更浅抽检

- 更紧的出口/瓶颈/`maxCops` 约束。
- 抽检深度与时间预算更紧，保证生成延迟可接受。
- 仍拒绝「小偷一步必胜 / 警察无切断可能」的盘。

### 4.5 产品文案口径

- **易**：经搜索验证，正确下可赢。  
- **中/难**：可围堵结构 + 抽检；极少数边界盘若被更强 AI 打穿，记已知风险，用 seed 复现修生成器。

## 5. 小偷 AI：尽量完美 + Worker + 降级

### 5.1 目标

轮到小偷时，在「警察后续也会尽量堵」的前提下，选择最有利于逃出的一步——**交替博弈**，而非仅跟当前最短 BFS。

### 5.2 运行时

- 对局 `getAIMove` / 提示：默认 **Web Worker**，避免阻塞 UI。
- Worker 内可对根走法分片并行；Node 测试保留纯 TS 同步路径。
- Worker 不可用 → 主线程有界搜索。

### 5.3 搜索

1. 终局：踏入 `exit` → 小偷胜；无合法步 → 警察胜。  
2. 警察回合枚举 `place`（启发式剪枝：逃逸路径 / 割点候选优先）。  
3. 小偷回合枚举 `step`。  
4. 未终局评估：逃逸最短路、出口可达数、剩余 `maxCops`、割点压力等。  
5. 小图（11）优先搜到终局；中/大图在预算内加深。

### 5.4 降级链（必须可观测）

```
完美/深搜（Worker，预算内）
  → 超时：有界 minimax（降深）
    → 再失败：BFS 贪心（exit > 最短路 > 保可达）
```

实际档位写入 `stats.solverName` / trace；UI 可显示「本步：完美 / 有界 / BFS」。

### 5.5 警察 hint / `solve`

- 同一对抗引擎，**警察视角**取推荐 `place`。
- 可视化保留 `escape-path`；主变例树可视化可二期。

### 5.6 手感

- AI 思考中：轻量「思考中」提示（i18n）；避免重复调度打架。
- 等 Worker 返回后再落子；对本游戏尊重/使用真实思考耗时（修复「固定 600ms 忽略 delay」至少覆盖本游戏路径）。

## 10. 开放风险

- 易关严格验证在最坏分支仍可能慢 → 需时间预算 + 构造偏向可解形态以降低重试。  
- 中/难「必胜」是工程保证而非数学证明 → 文案必须诚实。  
- 主线程 AI delay 平台问题：本升级至少让 thief-siege 路径等 Worker 完成后再 `applyMove`。
