## 1. 动机与定位

把经典英式孔明棋做成 Ludus 插件：默认 **L1 可玩、零说教**；教育侧栏（L2/L3）要求 **全面、严谨、有趣**——既有形式化与复杂度，也有「为什么这步妙 / 对称如何救命」的故事感，而不是干巴巴的百科摘录。

与围堵小偷不同：这是单人跳跃消子谜题，核心算法是 **状态空间搜索 + 对称约简**，不是对抗博弈。

## 2. 已确认决策

| 项 | 结论 |
|----|------|
| 棋盘 | 英国十字 **33 孔** |
| 通关目标 | 按难度分级：易 ≤3 子；中剩 1 任意；难剩 1 且在中心 |
| 求解器 | 完整教学求解器：最短/可达搜索 + 对称约简 + 搜索树可视化 |
| 关卡 | 经典中心空开局 + 精选残局包；生成器 = 挖空 + 验证可达目标 |
| 架构路线 | **A**：bitmask 状态 + Worker 搜索 + React Flow 教学可视化 |
| 教学侧栏 | **尽量全面、严谨、有趣**（见 §6） |
| 非目标 | 法式 37 孔、三角盘、任意生成盘的唯一最短证明、3D 物理 |

## 3. 身份与元数据

- **id**：`peg-solitaire`
- **中文名**：孔明棋
- **英文名**：Peg Solitaire
- **category**：建议 `category.search`（已有中英）
- **icon**：自选非侵入符号（如 `◉` 或棋类相关 emoji，实现时定，须 i18n 友好）
- **renderBackend**：`dom`
- **isFastSolver**：浅残局可 true；深搜走 Worker（`webWorker: true`）

## 4. 规则与状态

### 4.1 规则

- 33 孔英式十字；正交四向跳跃。
- 合法跳：`from` 有子、`over` 有子、`to` 为空，且三者共线相邻（预计算跳跃三元组表）。
- 执行：清空 `from`/`over`，填充 `to`。
- 交互：点选有子 → 高亮合法落点 → 再点落点；支持撤销/重做。

### 4.2 状态模型（示意）

```ts
/** bit i = 1 表示孔 i 有钉；孔编号 0..32 固定映射到英式几何 */
interface PegSolitaireState {
  pegs: number;           // bitmask，可用 bigint 若需要；优先 number + 分片或两个 number
  goal: 'le3' | 'one-any' | 'one-center';
  status: 'playing' | 'won' | 'stuck';
  // 可选：selectedHole: number | null 仅 UI，也可放 presentation
}

type PegSolitaireMove = { from: number; over: number; to: number };
```

实现可选：`pegs` 用 `number`（若 33 bit 放进两个 32-bit 或 BigInt）——计划阶段锁定一种，测试固定编码。

`isSolved`：`status === 'won'`（达到当前 `goal`）。

`stuck`：未获胜且 `legalMoves` 为空。

### 4.3 终局判定

| goal | 获胜条件 |
|------|----------|
| `le3` | `popcount(pegs) <= 3` |
| `one-any` | `popcount(pegs) === 1` |
| `one-center` | `popcount(pegs) === 1` 且中心孔有子 |

## 5. 难度、关卡与生成

### 5.1 难度映射

| 档 | difficultyRange | goal |
|----|-----------------|------|
| 易 | 1–33 | `le3` |
| 中 | 34–66 | `one-any` |
| 难 | 67–100 | `one-center` |

### 5.2 关卡来源

1. **经典**：中心空、其余满（主入口）。
2. **精选残局**：打包 JSON/TS 常量，每条标注可达目标与（若知）最优步数。
3. **生成器**：随机移除若干钉（保留可玩密度）→ 求解验证可达当前 `goal` → 失败重试；v1 **不**要求唯一最短。

### 5.3 难度分

综合：目标严格度、开局剩余子数、求解深度/分支估计。

## 6. 求解器、对称与可视化

### 6.1 引擎

- 预计算全部合法跳跃三元组。
- 搜索：回溯或 IDA*；哈希规范化状态（D4 对称：旋转+反射 ≤8）。
- 输出：一条解（优先最短，预算内）；`stats` 含 nodesExplored、timeMs、是否启用对称剪枝。
- Worker：深搜默认进 Web Worker；主线程保留同步路径供测试。

### 6.2 Trace / Viz

- `SolverTrace.type`：优先复用 `'search-tree'`，或新增 `'peg-search'`（实现时二选一写入 ADR）。
- React Flow：搜索树 / 主变例；节点展示剩余子数或压缩局面。
- 对称：L3 侧栏 + 可选小图展示「等价局面归并」，v1 不强制完整 8 拷贝动画。

### 6.3 产品能力

- `solve()` / hint / 逐步播放共用引擎。

## 7. 教学侧栏（全面 · 严谨 · 有趣）

教育是本游戏的差异化重点。默认折叠不打扰 L1；一旦打开，内容必须 **经得起推敲、读起来有趣味**。

### 7.1 组织原则

- **全面**：五段式齐全；L2 能讲清直觉与「为何会死局」；L3 覆盖形式化、复杂度、算法、对称、生成验证、与相关问题的边界。
- **严谨**：术语与数学陈述可核对；区分「已知结果 / 启发式 / 未证明」；引用经典结论（如英式中心目标可解、最优步数量级）时注明来源层级（教科书/社区已知/本求解器实测）。
- **有趣**：每段至少一个「钩子」——反直觉例子、失败名局、对称「偷懒」的笑话式类比、可动手的小挑战；避免纯定义堆砌。

### 7.2 L2（玩中学）建议骨架

1. **玩**：一句话规则 +「别把最后几步跳死」。
2. **思考**：为什么有的局面看起来空旷却无解？中心目标难在哪？
3. **揭示**：状态 = 钉子子集；一步 = 图上的跳跃边；目标 = 特定子集族。
4. **求解**：演示求解器如何「向前看」；对称如何把 8 个看起来不同的盘当成一个。
5. **出题**：换目标档 / 残局 / 生成一盘「保证能到达目标」的残局。

### 7.3 L3（专业向）建议骨架

- 形式化：配置空间大小 \(2^{33}\) 上界、可达子集远小；跳跃作为置换/集合运算。
- 搜索：回溯 vs IDA*；启发式（剩余子数、中心距离等）的局限。
- **对称约简（重点）**：\(D_4\) 作用；Burnside/轨道直觉（趣味版讲清即可，严格陈述给可选深入）。
- 复杂度：一般孔明棋变体与硬度直觉；英式特例「可解」不等于「任意残局多项式可解」。
- 实现对照：本仓库 bitmask、规范化键、Worker 预算、降级策略。
- 开放问题 / 延伸：法式盘、逆向生成「唯一最短」、与 Lights Out 类线性谜题的对比（不同代数结构）。

### 7.4 写作与验收

- 四份 md：`l2/l3 × zh-CN/en`，五段式标题与现有游戏一致。
- 验收主观标准：审阅者能指出至少 3 处「有趣钩子」与至少 3 处「可核对的严谨陈述」；无硬编码 UI 文案（走 i18n）；公式 KaTeX。
- 禁止：为凑字数重复；把未验证的「最优」写成定理。

## 10. 实现顺序（供后续 plan）

1. 几何编码 + rules + 测试  
2. 求解器（对称 + 最短/可达）+ Worker  
3. 生成器 + 精选残局 + 难度  
4. 插件 UI / registry / i18n  
5. 教学 md（加重 §7）+ viz + 文档  

## 11. 开放风险

- 33 孔全解搜索在无对称时可能慢 → 对称 + Worker + 预算必须到位。  
- 「有趣」写作质量依赖文案打磨，计划中单独留足 Task 给 L3。  
- BigInt vs 双 number 编码需在实现计划 Task 1 锁定并写死测试向量。
