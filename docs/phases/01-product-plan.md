## 1. 三层用户画像

### L1 · 纯娱乐玩家（主要流量入口，占目标用户 60%+）

| 维度 | 描述 |
|------|------|
| **代表人物** | 小陈，22 岁，大学生，等公交/排队时掏出手机玩一把 |
| **动机** | 消磨碎片时间，喜欢动脑但不费脑的小游戏；讨厌被"说教" |
| **场景** | 移动端浏览器（微信 H5 / 手机 Chrome），每次 3–10 分钟，碎片化 |
| **痛点** | 市面上大部分"益智游戏"要么太简单（无聊），要么太难（劝退），要么塞广告/付费；讨厌弹窗教程 |
| **目标** | 打开即玩，即时反馈，手感好；"这游戏挺有意思"——甚至不知道它和数学有关 |
| **关键行为** | 玩一局 → 赢了有反馈 → 换一关或换一个游戏 → 关闭。不点任何"原理/学习"入口 |
| **技术需求** | 低端手机可流畅运行，首屏 ＜ 3 秒，触控友好 |

### L2 · 玩中学泛人群（增长引擎，占目标用户 25%）

| 维度 | 描述 |
|------|------|
| **代表人物** | 小李，28 岁，前端开发，偶尔刷到算法题感到焦虑，想"轻松地学点东西" |
| **动机** | 玩好玩游戏的同时"顺便学点有用的"，不想啃教材；对"这游戏背后有什么数学"有好奇心 |
| **场景** | 桌面端为主（工作间隙），偶尔手机，每次 10–30 分钟 |
| **痛点** | LeetCode 枯燥，视频教程被动且无互动；想"动手"但不知从何开始；需要有人告诉他"为什么这样是最优的" |
| **目标** | 玩游戏 → 通关后点"揭秘"→ 看一句话原理→ 看求解器演示动画 → "哦原来是这样！" |
| **关键行为** | 玩几局 → 点"原理"→ 看 L2 卡片（一句话 + 复杂度）→ 看求解器动画 → 可能分享 |
| **技术需求** | 桌面端流畅，公式渲染清晰（KaTeX），求解器可视化可交互 |

### L3 · CS/数学专业学习者（核心重度用户，占目标用户 15%）

| 维度 | 描述 |
|------|------|
| **代表人物** | 小王，20 岁，CS 大二，正在学算法设计与分析，想通过"可动手"的方式理解课堂知识 |
| **动机** | 把课本上的抽象算法（高斯消元/DLX/Minimax）变成可操作、可观察的具体过程；想自己改参数、比较不同算法 |
| **场景** | 桌面端为主，长时间沉浸（30 分钟–2 小时），可能配合课程学习 |
| **痛点** | 课本全是伪代码和证明，缺乏直观感受；OJ 只有输入输出，看不到算法中间状态；不知道"为什么要这样设计算法" |
| **目标** | 玩 → 形式化定义 → 看完整推导（LaTeX）→ 看求解器源码/伪代码 → 自己调参数出题 → 理解为什么这个复杂度 |
| **关键行为** | 阅读完整教学文档（中/英）→ 交互式算法可视化（React Flow/D3）→ 调关卡生成器参数 → 比较不同求解策略 → 可能贡献 |
| **技术需求** | 代码可读性高，求解器可单步调试，可视化可交互探索，教学文档 LaTeX 渲染正确 |

## 2. 用户故事地图

### Epic 0 — 合集框架与导航（阶段 6，但骨架在阶段 4 搭建）

```
作为 任何玩家，我打开 Ludus 后能看到游戏合集主页，选择想玩的游戏，快速进入，这样我不用每次记住 URL。

Feature: 合集主界面
├── Story: 首页游戏网格卡片（封面图 + 标题 + 一句话简述），点卡片进入游戏
├── Story: 按领域分类浏览（图论 / 博弈 / CSP / 搜索 / ...）
├── Story: 关键词搜索（支持中/英游戏名搜索）
├── Story: 移动端底部 Tab 导航，桌面端侧边栏

Feature: 跨游戏状态
├── Story: 每款游戏的最近进度保存在本地（localStorage）
├── Story: 已通关关卡标记
├── Story: 游戏间无强制顺序，任意自由切换
```

### Epic 1 — 单款游戏核心体验（阶段 4/5，每款游戏重复）

```
作为 L1 玩家，我想打开 Lights Out 后能立刻开始玩，规则在操作中自然理解，不被任何教程打断。

Feature: 开箱即玩
├── Story: 进入游戏即显示可操作棋盘，无需教程弹窗
├── Story: 首次操作后出现极简提示（≤1 行，如"点亮所有灯"），3 秒后自动消失
├── Story: 胜利时有明确且令人愉悦的反馈（动画+音效），清晰显示"再玩一关"/"换个游戏"
├── Story: 棋盘大小自适应屏幕（3×3 / 5×5 / 可变）

Feature: 基础操作
├── Story: 点击格子切换灯状态，即时视觉反馈
├── Story: 撤销/重做（不限步数）
├── Story: 重置本关（回到初始状态）
├── Story: 跳过关卡 / 选择关卡（预生成列表）
```

```
作为 L2 玩家，我通关后想点"揭秘"看这游戏背后的数学原理，用一句话讲清楚。

Feature: 渐进式揭示 — L2 层
├── Story: 通关后出现"揭秘"入口（不弹窗，在胜利界面底部）
├── Story: 点击展开 L2 知识卡片：一句话原理 + 复杂度归类 + 小示例
├── Story: 求解器演示：可播放/暂停/单步的动画，展示算法如何解本关
├── Story: 随时可关闭教育层回到游戏
```

```
作为 L3 学习者，我想完整理解 Lights Out 的 GF(2) 线性代数建模、高斯消元解法、以及如何生成唯一解关卡。

Feature: 渐进式揭示 — L3 层
├── Story: L2 卡片底部有"深入学习"入口，展开完整教学
├── Story: 形式化定义（LaTeX）：状态向量、转移矩阵、方程组
├── Story: 复杂度归类与论证（GF(2) 高斯消元 = O(n³)，P 类）
├── Story: 求解器源码/伪代码展示（语法高亮，关键行有注释）
├── Story: 交互式可视化（React Flow：消元步骤的可视化；D3：零空间基向量）
├── Story: 关卡生成器参数面板：调整棋盘大小、难度、查看生成原理
├── Story: 教学内容中/英切换，独立于 UI 语言

Feature: 出题（关卡设计单元）
├── Story: 输入参数（大小 n），一键生成随机可解关卡
├── Story: 生成唯一解关卡（通过求解器验证零空间维数 = 0）
├── Story: 生成已知最优解关卡（反向 BFS）
├── Story: 查看难度指标（消元步数 / 零空间维数 / 最少步数）
```

### Epic 2 — 跨游戏横切能力（阶段 3/6）

```
Feature: 统一渐进式揭示组件
├── Story: 可复用组件，L1(游戏本体) → L2(知识卡片) → L3(完整教学)，每个游戏只需填充内容数据
├── Story: 内容数据按"语言(zh/en) × 深度(L2/L3)"组织，与组件解耦

Feature: i18n
├── Story: 所有 UI 文本使用 i18n key，无硬编码
├── Story: 运行时切换语言（zh ↔ en），UI 即时刷新
├── Story: 默认跟随浏览器语言设置，回退中文
├── Story: 教学内容中/英双份，LaTeX 公式语言无关

Feature: 算法可视化（React Flow + D3）
├── Story: 可视化组件声明式接口：接收算法步骤轨迹数据，渲染为图/树/矩阵变换
├── Story: 播放控制：播放/暂停/步进/调速
```

## 3. MoSCoW 优先级矩阵

### 🔴 Must Have（MVP 必达，缺一不可交付）

| ID | 条目 | 所属 Epic |
|----|------|-----------|
| M1 | **Lights Out 完整游戏**：可玩棋盘、合法操作、胜利判定、撤销/重做、多关卡 | Epic 1 |
| M2 | **Lights Out 求解器**：GF(2) 高斯消元，正确求解任意合法棋盘状态 | Epic 1 |
| M3 | **Lights Out 关卡生成器**：生成可解关卡（含唯一解关卡），附难度度量 | Epic 1 |
| M4 | **五段式教学 × 1 款**（Lights Out）：L2 知识卡片 + L3 完整教学（中/英） | Epic 1 |
| M5 | **算法可视化 × 1 款**：Lights Out 高斯消元步骤可视化（React Flow 或 D3） | Epic 1 |
| M6 | **统一渐进式揭示组件**：L1/L2/L3 切换，可复用接口 | Epic 2 |
| M7 | **i18n 基础**：中英双语 UI 切换，默认中文，所有文本无硬编码 | Epic 2 |
| M8 | **合集骨架**：首页游戏卡片（≥1 款可玩）+ 路由框架 | Epic 0 |
| M9 | **Core 层框架无关**：游戏规则/求解器/生成器零 UI 依赖，可在 Node/Worker 运行 | Epic 1 |
| M10 | **Web 部署**：静态站点可部署，Web Worker 运行重计算不阻塞 UI | Epic 1 |
| M11 | **单元测试**：规则/求解器/生成器核心逻辑有测试覆盖 | Epic 1 |

### 🟡 Should Have（MVP 尽力包含，不阻塞发布）

| ID | 条目 | 所属 Epic |
|----|------|-----------|
| S1 | **数独游戏**：第 2 款游戏，验证插件化架构 | Epic 1 |
| S2 | **Nim/Wythoff 游戏**：第 3 款游戏 | Epic 1 |
| S3 | **合集搜索与分类** | Epic 0 |

| S7 | **求解器 Web Worker 集成**：>500ms 求解异步执行 | Epic 1 |

### 🟢 Could Have（锦上添花，资源允许时做）

|----|------|-----------|
