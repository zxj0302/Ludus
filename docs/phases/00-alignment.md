## (a) 愿景与差异点复述（≤10 行）

1. **Ludus 是什么**：一个寓教于乐的大型小游戏合集，把枯燥的算法/数学问题包装成第一眼就"好玩"的经典小游戏。
2. **核心铁律**：**游戏性永远第一**。教育是可选增值层，默认折叠，绝不因"塞知识"损害手感；纯娱乐玩家（L1）零负担。
3. **差异点（我们 vs 市面）**：现有产品要么"只玩不讲算法"，要么"只讲不可玩"。Ludus 把五个维度并排呈现：**可玩游戏 + 形式化抽象问题 + 复杂度归类 + 可运行求解器 + 关卡生成器**。
4. **三层用户同一实例**：L1 纯娱乐（默认）、L2 玩中学（轻量揭示）、L3 专业学习（完整推导/代码/调参）——通过统一"渐进式揭示组件"按需切换，非三套产品。
5. **数学/CS 覆盖面**：16 大领域 70+ 款候选游戏，从图论、博弈论、CSP/SAT、线性代数到计算复杂性、群论、信息论，每款均含求解器 + 生成器 + 算法可视化。
6. **平台策略**：Web 首发为第一入口；架构保证不重写即可经 Tauri（桌面）和 Capacitor（移动端）套壳。微信仅以 H5 覆盖最低获客需求，小程序列为未来独立任务。
7. **渲染双轨**：游戏本体默认 DOM + Framer Motion，重网格/高频动画可切换 Canvas；算法可视化用 React Flow（图/树/自动机）+ D3.js（自定义数据可视化），两者按需懒加载。
8. **国际化第一公民**：默认简体中文，完整支持英文，所有 UI 文本走 i18n 体系，禁止硬编码；教学内容中英双份，公式语言无关。

## (c) 成功标准与非目标

### ✅ 成功标准（如何判断项目成功）

#### 产品层面

| #  | 标准                                                              | 衡量方式                                                                      |
| -- | ----------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| S1 | **L1 玩家可在 30 秒内上手任一游戏**，无需阅读说明           | 用户测试：给一个从未见过的游戏，计时到首次有效操作                            |
| S2 | **教育内容完全不打扰 L1 玩家**                              | 用户测试：L1 玩家完成 3 局后，问"你觉得游戏在教学吗？"，回答"没感觉"          |
| S3 | **L3 学习者能从游戏中获得可运行的算法理解**                 | 用户测试：CS 本科生玩后能独立描述该问题的形式化定义、复杂度、至少一种求解思路 |
| S4 | **中英切换覆盖所有 UI 与教学内容**，无硬编码字符串残留      | 自动化检查 + 人工抽查                                                         |
| S5 | **每款已交付游戏含至少一个正确求解器 + 一个可解关卡生成器** | 自动化测试：1000 次生成→求解器验证→断言合法且可解                           |

#### 技术层面

| #   | 标准                                                             | 衡量方式                                                   |
| --- | ---------------------------------------------------------------- | ---------------------------------------------------------- |
| S6  | **Core 层零 UI 依赖**，可在 Node / Web Worker 中独立运行   | CI：在 Node 环境运行 Core 全部测试（不含 jsdom）           |
| S7  | **新增游戏 = 新增模块，不改核心**                          | 代码审查：新增第 3 款游戏时，`packages/core` 无 diff     |
| S8  | **Web 首发可部署为纯静态站点**                             | `apps/web` build 产物可通过任意静态 HTTP 服务访问        |
| S9  | **Tauri/Capacitor 套壳可运行**（至少 Lights Out 验证通过） | 阶段 4 交付 Tauri 壳 + Capacitor 壳的最小可跑版本          |
| S10 | **重计算不阻塞 UI**（求解器 > 500ms 走 Web Worker）        | Performance API 测量：主线程帧率在求解器运行时不低于 30fps |

### ❌ 明确非目标（做什么会偏离航线）

| #  | 非目标                                         | 理由                                                                                              |
| -- | ---------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| N1 | **不做后端/用户系统/云同步**（MVP 阶段） | 增加运维成本、延迟交付、与"纯静态部署"冲突。用户进度存 localStorage；未来若加账号系统，为独立决策 |
| N2 | **不做多人联机/对战/排行榜**             | 核心价值是"单人解谜 + 学习"，多人引入网络同步、匹配、防作弊等巨大复杂度，稀释焦点                 |
| N3 | **不做游戏内付费/广告/商业化**           | 当前定位为教育公益项目，不引入商业化约束扭曲设计                                                  |
| N4 | **不做自研物理引擎/3D 渲染**             | 游戏品类聚焦 2D 回合/步进式逻辑谜题，3D 和物理引擎是另一个品类                                    |
| N5 | **不做"AI 出题/LLM 生成关卡"**           | 关卡必须经求解器验证可解性/唯一解/最优解，LLM 生成不可控、无法保证正确性。传统程序化生成是正解    |
| N6 | **不追求实现 backlog 全部 70+ 款游戏**   | Backlog 是长期菜单，实际交付取决于增量节奏。MVP 聚焦 3 款（Q7 建议），后续按优先级逐款推进        |
| N7 | **不追求"比 AAA 游戏好看"的美术**        | Ludus 是逻辑谜题合集，美术目标为"干净、清晰、有风格、手感好"，不卷入 AAA 级资产竞争               |
| N8 | **不做微信小程序原生版本**               | 以微信内 H5 覆盖；小程序版本列为未来独立任务，不约束主架构（ADR-009）                             |
| N9 | **不做桌面原生精品化/Steam 发布**        | 桌面仅以 Tauri 轻封装覆盖（ADR-010）                                                              |
